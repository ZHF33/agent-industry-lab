# 工程记录

## 交付范围与审查
2026-11-08。复用 inspection-reconciliation-review 的 LangGraph/API/n8n 控制骨架，独立实现申请量、实领、退回、逐件余额及异常核算。本案例是新的备件领料业务场景。

静态审查源码 AST、JSON、文档引用、工作流连接、工具白名单与轮数限制。测试代码提供10项数量/契约检查及3项脚本化图流程检查，未执行测试、模型推理、平台导入或课堂代码。不存在生产验证结果。

预期合成结果 BEARING-A 净领7、差异-3；SEAL-B 净领5、差异+1；FILTER-C 净领-1、差异-2并标记退回超过领出。负净量保留为证据，需人工追查遗漏领出或跨申请退料。空流水保留申请缺口，重复编号拒绝。

## 逻辑与失败处理
模型四轮、每轮三工具，三项成功取证与至少一个来源引用后才能交审核。工具错误反馈给模型修正；无证据、空回复、超轮、网络异常返回失败，不形成完成报告。工具白名单和申请编号由应用校验。审核在 checkpoint 中暂停，经有姓名的 approve/reject 恢复。共享密钥不能证明 reviewer 的真实身份，实名认证列为生产后续工作。

API 单进程非阻塞锁避免并发覆盖；忙时429。内存检查点随重启丢失，重新提交可能产生新报告。没有业务写入，报告不会扣库存。没有逐笔时间与跨申请追踪，当前只是给定快照的汇总核算，不能发现先退后领等顺序问题。申请与快照虽有版本检查，完整性仍由输入来源和人工确认；100行限制不能证明导出完整。
