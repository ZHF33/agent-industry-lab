# Agent 基建学习与实战框架

这是持续更新的课程框架，不绑定具体日期、月份或篇数期限。按前置知识与项目需要推进，完成一个学习单元再进入下一层。

| 模块 | 内容 | 实战目标 |

## 每个主题的递进层次

1. 场景：业务上为什么需要；没有它会发生什么。
2. 原理：核心机制、术语、前提和失败边界。
3. 实现：从最小代码开始，逐步解释每一步。
4. 集成：接入仓库实际项目，说明数据流和责任边界。
5. 故障：复现典型失败，观察日志和状态。
6. 验证：构造测试，检查业务结果而非只看接口成功。
7. 取舍：比较方案，说明什么时候采用、什么时候不必采用。
8. 复盘：课堂练习、参考答案、能力缺口与下一主题。

这些层次可以合并为一篇充分讲透的课程，也可分成多篇有独立学习目标的进阶课；不为了凑数量把内容切碎。

## 课程组织与持续更新

- 每篇标明前置知识、学习目标、关联项目、代码位置、验证范围和资料来源。
- 已发布索引记录成果，待讲主题单独列候选；不预写完成记录。
- 以基础 → 实现 → 工程 → 综合实战推进。同一组件的进阶内容必须增加新的能力。
- 讲解与 Agent/Skill 项目共用代码；复杂案例持续迭代，定期形成综合交付。
- 新工具先核查官方资料、维护状况与兼容性，再纳入课程；不要追热点替代基本原理。
- 所有底层能力都评估，按场景选用，写清已实现、未验证或暂不需要及原因。
- 保留持续每日更新的任务安排；课程正文和框架不写固定日历，不承诺固定期限完成。
- 草稿先在本地呈现供用户审阅，确认后再发布该课程；对已认可的课程组织方式继续执行。

## 教学质量标准

讲义必须带读者完成“看到现象 → 提出问题 → 建立机制 → 读懂代码 → 动手验证 → 解释边界”，不能只有工具名单或概念摘要。

每个代码实验给出准备条件、运行命令、预期结果、实际结果和限制。指出现有实现的真实不足，不把建议改进写成已完成。提供思考题与解释性答案。官方资料用于核实事实，不替代原创讲解。
