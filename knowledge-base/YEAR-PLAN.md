## 滚动更新规则

- 全年保留方向，未来四周细化，未来七天明确交付；每周更新本节日期与安排，保留已发布日志。
- 每篇记录 Day 编号、实际日期、前置知识、学习目标、关联项目、示例路径、验证命令和结果、局限及官方资料核查日期。
- 延迟时保留欠项并调整日历，不补造完成记录；365 篇是目标，不是假定成果。每日任务同时推进工程增量与知识讲解。
- 新技术先入候选池，核实维护状态和官方接口后替换尚未开始的主题，记录替换原因。
- 每月复盘知识缺口和工程案例，产出一项可运行综合交付；复杂项目允许跨月推进。
- 年末总结后进入进阶实战，继续编号与新周期，不重复第一篇。
- 所有示例脱敏；区分离线、模型、平台与生产验证，保持 MIT 与 GitHub Actions 关闭。
