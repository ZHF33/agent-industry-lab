# 第38讲 事件扫描与并发容量

## 停车位什么时候不够

车库有两个相同的车位。今天四人各预约半小时或一小时，管理员要知道是否有三辆车同时在场。把预约总数四拿来和两个车位比较，会把全天陆续到访误报为拥堵。只看一张预约则找不到同时争用。车位类比帮助理解占用数，现场月台还涉及车型、操作时长和安全要求，本课先假定车位可互换，且没有交接缓冲。

**小问题**　同一个车位 10:00 到点释放，下一辆 10:00 可以开始吗？

**解答**　在本课约定下可以。每段预约包含开始时刻，结束时刻已释放，写成半开区间 [开始, 结束)。若现场要求清场十分钟，应把这个时间纳入占用窗口再算。

## 只在占用变化处计算

把每个预约变成两条事件，进入时加 1，离开时减 1。事件是对某个时刻发生变化的记录。记同一时刻 t 的增量和为 Δ(t)，当时占用为 R(t)，前一段占用为 R₀，则 R(t) = R₀ + Δ(t)。下一个事件到来前，占用保持不变。按时间从前向后算一遍叫扫描。将一时多件事先合并，就不会在 10:00 的中间操作步骤凭空看到短暂超额。若月台容量 K 固定，当 R(t) > K 时，该整段缺 R(t) − K 个。

| UTC 时刻 | 发生变化 | 到下一时刻的占用 |
| --- | --- | --- |
| 09:00 | A +1 | 1 |
| 09:15 | B +1 | 2 |
| 09:30 | C +1 | 3，缺 1 |
| 10:00 | A −1、C −1、D +1 | 2 |
| 10:15 | B −1 | 1 |
| 10:30 | D −1 | 0 |

相较第25讲半开区间覆盖，这次保留每段同时占用数。区间的并集能说明“有没有人占用”，无法从合成后的一整段反推出峰值是 1 还是 3。排序只需处理每个预约的两个端点，无需生成每分钟的表，秒级预约同样适用。若容量随时间变化，也要把容量变化时刻加入端点。

**小问题**　只把容量从 2 改成 3，哪项结果变化？

**解答**　峰值仍为 3，超额条件由 3 > 2 变成 3 > 3，缺口列表为空。容量是与需求比较的尺度，不改变原始预约。

## 课堂实验

准备 Python 3.11 或更新版本。打开终端，从仓库根目录运行 [课堂脚本](examples/occupancy_sweep_lab.py)。

```powershell
python knowledge-base/examples/occupancy_sweep_lab.py
```

脚本用整数表示 09:00 后的分钟数。第一段循环校验结束晚于开始，然后用 Python 标准库的 Counter 按时间累加带正负号的变更。第二段把当前时刻与后一个时刻配对。先加净变更，再检查这一小段的占用。最终返回峰值和所有超额时段。09:30–10:00 对应 (30, 60)，第三个值 1 是缺口。静态核对与手推已完成，课堂示例未执行。

```text
capacity=2 peak=3 conflicts=[(30, 60, 1)]
capacity=3 peak=3 conflicts=[]
```

若收到 start must precede end，先查是否把开始、结束颠倒。若只在相接处出现缺口，查是否把同刻开始单独提前计算。工程服务还需将时区不同的时间归一到同一尺度。比如 04:30、偏移 −05:00 对应 09:30 UTC，不能按字符串表面排序。
