# 第35讲 累计计数器与重置证据

你在记一把刀具用了多少次，昨天写 88，今天屏上显示 5。昨天到今天本来应该只增不减。可能换了刀具，也可能系统重置、记录乱序或读错设备。好比汽车里程表，数字降低时先查表是否换过。里程表类比说明读数的连续性，具体原因需要系统事件和现场记录。

## 两个数字能说明什么

累计计数器保存从某次起点开始累计发生的次数。快照是某一时刻截取的读数。把上一时刻读数记为 P，把当前读数记为 C，若二者属于同一累计序列，期间新增是 C−P。例中 80 到 90，差为 10。若只把 C 改为 5，差变成负数，表示连续性假设需要核对。把负值强制改成零会丢掉异常信号。

下批计划次数记为 N，寿命上限记为 L。本例假设批次按计划完成，预计读数 C+N。若当前为 90，上限为 100，计划 10 次后恰好为 100。只把计划改成 11 次便超出。这个包含上限的规则是课堂策略，现场需核对企业口径。

小题。上一读数为零是否等同缺值？零是一条有效观测。缺值表示没收到证据。同一规则若把二者混用，会误把初次使用判为缺记录。

## 实验与逐步观察

准备 Python 3.11+，从仓库根目录运行 [课堂示例](examples/counter_reset_lab.py)。

```powershell
python knowledge-base/examples/counter_reset_lab.py
```

脚本先用 None 表示缺读数。然后检查 C 是否小于 P。只有读数齐且未回退时才相加，并比较上限。三条证据完整性分支能避免在 None 上做算术。输入 80、90、10、100 时，预期第一行显示 fits 100。随后只把计划改为 11，预期 exceeds 101。第三行 regression None，第四行 missing None。实际已做静态检查，请运行后另记真实输出。

## 工程位置与失败排查

刀具寿命 Agent 的规则工具先检查设备范围、时间先后、读数类型和上限，再为每把刀具输出原始读数与结论。模型选择工具、读取结果并解释。班组长凭台账核对换刀、复位及下批用量。[案例与运行说明](../examples/tool-life-review/README.md)

时间乱序时查采集时区和时间戳来源。若重启令计数清零，按实例或运行世代保存记录是一种做法。物理刀具可能并未更换，此时业务寿命需要从可信台账恢复，不能凭 5 次推定剩余 95 次。当前项目只保留两个快照，也无法发现重启后计数再次超过旧值的情形。

练习一。上一读数 0、当前 2、计划 3、上限 5，预期什么？预计为 5，按样例包含上限，应为 fits。练习二。上一读数 88、当前 5，是否能断定换刀？不能。至少还需刀具实例或换刀记录。交一张含 P、C、N、L 的手算表，并说明每种异常该找谁查证。
