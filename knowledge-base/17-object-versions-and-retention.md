# 第十七讲｜文件“没了”，旧版本一定也没了吗？对象存储、版本与保留

[配套Agent](../examples/object-retention-review/README.md)只读合成元数据。今天不登录云平台，不下载文件，不执行删除或恢复。

## 1. 从档案柜开始，但别把云存储当文件夹

客服打开一份合成收据的链接，页面显示“找不到”。同事说：“文件删除了，备份也没有。”这句话连续跳过了三次核查：链接指哪个对象、普通读取选中了哪个版本、旧数据还在不在。

想象档案柜里，“收据A”是一张索引卡。柜里可能保存多次修订，每张带不同编号；前台索引现在换成“已撤下”。撤下索引和烧掉所有底稿是不同动作。

类比边界：对象存储没有真的柜子，权限、网络、版本规则和生命周期由系统控制；有版本也不等于能读，更不等于有独立备份。

先回答：页面404足够证明所有版本已不存在吗？不够。它描述一次请求的结果，不能替代版本清单和权限核查。

## 2. 四个名称，分别解决四个问题

**对象存储**把内容作为对象保存，通过接口按名字访问。**桶（bucket）**是组织和管理对象的容器。**对象键（key）**是桶内对象的名字，例如`demo/receipt.txt`。其中斜杠常用来组织前缀，不能直接认定背后存在传统文件系统目录。

**版本标识（version ID）**用来区分同一键的不同版本。调查时只记key不够：你可能检查了新版状态，却引用旧版保留信息。对版本的精确身份应包含服务/账户范围、桶、键及version ID。本例用固定object_id映射一个合成对象，缩小了真实身份模型。

**元数据**是描述对象的数据，如版本号、大小、观察时间；**对象正文**才是文件字节。拿到元数据不表示已经下载正文；看见大小也不能证明文件内容正确。

小问题：两个桶都叫`receipt.txt`，能当同一个文件吗？不能，键的名字只在其容器及服务身份范围内有意义。

## 3. 用三次动作理解版本机制

以下限定“已开启版本控制”的示意场景，不覆盖暂停版本控制、空版本、生命周期清理等所有配置。

| 动作后 | 同一key下的已知版本 | 普通读取选择 |
| --- | --- | --- |
| 第一次写入 | data-v1 | data-v1 |
| 第二次写入 | data-v2、data-v1 | 当前data-v2 |
| 普通删除请求 | marker-v3、data-v2、data-v1 | 当前marker-v3 |

在S3这个具体实现中，普通删除可能放入**删除标记（delete marker）**。它不带文件正文。当前版本若是删除标记，不指定版本的读取可能返回404；这与旧版本已经全部物理删除不同。精确指向历史数据版本是另一种读取，仍要检查授权等条件。[官方删除标记说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DeleteMarker.html)

这个表不是让你去删标记恢复文件。恢复属于写操作，必须有单独授权、影响评估和执行记录。今天只解释“为什么表面不存在不能推出全部消失”。

## 4. 版本、保留、备份不能互相替代

**版本控制**回答“是否留有同名对象的历史版本”。**保留期限**回答“某个版本在何段时间受删除等限制”。**法律保留（legal hold）**是另一类可持续生效的保留标志；名字不代表程序有权判断法律责任。**备份**需要独立评估隔离、覆盖范围和恢复能力。

S3 Object Lock提供与对象版本有关的保护机制；具体保留类型、模式、权限和例外必须查对应平台文档。本课只用“固定截至时间”和“hold标志”解释证据，不模拟全部规则。[Object Lock官方概述](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html)

反例：v1显示保留到下个月，v2没有对应记录。不能把v1的限制自动复制给v2；也不能把v2“没有查到记录”解释为“无限制”。可能根本没拿到完整元数据。

## 5. 一次小数字判读

假定两份快照都在12:00采集，业务约定最多允许60秒证据年龄，审核时刻为12:00:30。

```text
年龄 = 审核时刻 - 观察时刻 = 30秒
30 <= 60：满足本例的新鲜度约定
```

这里“新鲜”只表示采集时间足够近，不表示内容可靠、不表示审核瞬间没有变化。60秒是合成场景的策略，不是云平台标准。

对data-v1，记录保留截至下月，hold=false。在本例审核时刻仍有保留限制记录。若截至时间改成昨天，hold=true，仍有hold限制记录。若两个都不活跃，输出只能是“未记录活跃限制”，不能输出“允许删除”。实际权限、其他政策、业务授权和云平台状态尚未被这个公式判断。

再问：审核时间早于快照采集时间时能算负年龄并通过吗？不能，这会拿“未来证据”支持过去决定；Agent抛错，先查时区和时间来源。

## 6. 离线实验：同一清单，两种选择

前提：已有Python 3.11+。**终端**是输入命令的窗口，Windows可用PowerShell；`cd`表示切换目录，`python`表示调用Python解释器。没有Python时先做下面纸笔表，不必安装云SDK。

从仓库根目录：

```powershell
python --version
python knowledge-base/examples/object_version_lab.py
```

这是完整可运行的离线例子：[object_version_lab.py](examples/object_version_lab.py)。只操作内存合成字典，不访问云。按代码推导的预期输出，尚未实际执行：

```text
default: hidden_by_marker
explicit: synthetic receipt
data_versions: 1
```

分段理解核心动作，下列是文件中的片段，不能独立运行：

```python
candidates = [v for v in versions if v["current"]]
```

输入是版本字典列表；`for`逐项检查，`if`只保留当前项。默认读取先选中marker-v2。函数发现它是delete_marker，返回“被标记遮住”，不返回正文。

```python
candidates = [v for v in versions if v["id"] == version_id]
```

这次输入明确版本data-v1，选择条件改变，旧版合成正文仍可从内存表中取出。不是脚本恢复了云文件，只是展示选中的行不同。

最后一行统计kind为data的条目数，说明“默认读取不返回正文”和“清单中没有数据版本”并不等价。这个实验不实现S3 HTTP响应、授权、分段上传或一致性全部语义。

## 7. 与Agent逐项对照

工具一取版本清单，工具二取同一对象的逐版本保留记录，工具三比较身份、时效、完整性和限制。模型负责按结果组织调查建议，不能覆盖确定性报告。

真实不足：目前元数据内置，`complete=true`是合成前提；没有真实分页、存储查询、签名认证和对象校验。生产适配必须完成分页、限定桶/键范围、保留请求身份与时间，不能取得第一页就声称清单完整。当前`object_readability=unknown`正是因为没执行真实读取。

## 8. 常见故障与识别

| 现象 | 先检查什么 | 不能直接推出什么 |
| --- | --- | --- |
| 普通读取404 | key、版本、删除标记、服务响应 | 全部历史数据被清除 |
| 读取403 | 身份、权限、端点与访问路径 | 对象必然不存在 |
| 清单只有一页 | 分页是否取尽、权限范围 | 只有这些版本 |
| 保留信息缺项 | 是否精确查同一版本、采集完整性 | 该版本可删除 |
| 记录时间在未来 | 时区、时钟、输入日期 | 未来信息可支持当前结论 |
| 重启后审核线程不见 | 本例使用内存检查点 | 云对象被删除 |

命令提示“找不到python”表示解释器路径问题；提示“can't open file”先查当前目录和文件名；这些都不是云端异常。

## 9. 工程取舍与下一步

只读元数据足够做初步分诊，能避免下载敏感正文，但不能证明内容完整或可恢复。版本能缓解误覆盖风险，也会增加存储与清理成本；独立备份仍需检查。限制删除能够降低部分风险，也可能影响清理流程；不可由Agent随意更改。

本例无须Redis、向量库或Dify；对象身份精确查询比模糊检索合适。真实接入优先做最小只读权限、完整分页、来源与时间、租户隔离，再考虑持久审计和审批恢复，不先加入更多框架。

## 10. 课堂作业与答案

1. key相同而version ID不同，是否能用一条保留记录覆盖两者？**不能。**必须匹配版本身份；缺项转人工。
2. 当前是删除标记，旧版有正文，是否已经证明可恢复？**没有。**还缺真实授权、正文完整性、恢复步骤和隔离测试。
3. retain_until已经过去，hold=false，能批准删除吗？**不能。**它只是本例元数据里未记录活跃限制，还缺权限、政策和业务授权。
4. 将示例data-v1的body改成另一个合成句子，默认输出是否变化？**不变。**默认仍选删除标记；精确版本的正文输出才变化。

当日交付：画出桶→key→两个版本的关系；手工解释三行预期输出；写一句“现有证据支持什么”和一句“还缺什么证据”。只写“已删/未删”不算完成。
