# 第九讲：三张单都有数字，为什么不能直接相减？

配合采购三单复核Agent。讲清关联键与数据连接，

## 1. 从三个文件夹开始

采购单写10件，仓库单写8件，发票写10件。看起来少收2件，但如果仓库单属于另一个采购单，这个结论根本没有基础。

**关联键**就是让两份记录指向同一个业务对象的字段，例如采购编号。生活类比是快递单号：不能只因为两个包裹都写“10件”就认定属于同一订单。类比边界：真实订单可能多行商品、多次收货、改版与退货，仅一个编号仍不够，需要行号、单位、版本等共同确定对象。

小问题：单价和数量都一样，是同一笔订单的证据吗？不是，数字相同不是身份相同。

## 2. 连接数据前先定比较口径

数据库里的join通常译为连接，把有关联的记录放到一起。可以先不用数据库理解：用采购编号找到订单，再用同编号找收货记录和发票。但仍须核对商品编号SKU和单位。10箱不能直接与8件比较，CNY价格不能直接与USD价格判断相等。

项目先分别获取订单、单据，再由匹配工具检查po_id、sku、unit和currency。发现不一致就列出问题，人工先解决身份和口径，不能看其他数值“差不多”就付款。

这个例子用内存字典，逻辑相当于小型查表。数据库不必先安装，但查表条件必须明确。以后换SQL时参数化查询和对象权限也必须保留，数据库不会自动知道业务上哪张单该连接。

## 3. 一对多为什么会把金额算大？

一张订单可能有两条收货记录和三条发票记录。直接全部连接，会得到六条组合；如果再把数量相加，同一收货记录可能重复三次。这叫连接后的重复放大，不是仓库真的多收了货。

应先定义粒度：一条记录代表什么？如果每条是一次收货，需要先按订单行汇总已确认的净收货，再与对应发票行比较。退货、作废与冲销都影响净额。本项目只实现单商品行、单收货、单发票，因此不声称解决了多批复杂对账。

小问题：把重复行全部删除能解决吗？不能，相同数量可能是两次合法收货。需要业务事件编号来区分，不能只按数值去重。

## 4. 代码一步步看

说明片段，不可独立运行：

```python
for key in ["po_id", "sku", "unit"]:
    if len({record[key] for record in records}) != 1:
        issues.append(key + "_mismatch")
```

输入是三张记录。集合收集某字段出现的不同值；只有一个不同值，说明这一字段一致。超过一个值就标记不一致。该检查不能证明记录真实，只说明字段值相同。实际代码还核对数量类型、金额范围及计算式。

```python
if invoice["quantity"] > receipt["quantity"]:
    issues.append("invoiced_above_received")
```

这只是异常线索。先确保同商品、同单位，再解释数量。如果身份不一致，不能把这条告警当最终财务事实。部分收货可能合法，但应由业务人员决定是否分批结算，Agent没有付款权。

## 5. 金额算对为什么仍然不够？

示例发票10件×12.50=125.00，算式正确。但收货只有8件。算术正确、关联正确、业务可结算是三个不同问题。模型负责解释缺项与建议，工具输出matching_report保留原始问题，人工核对原单据。

金额使用Decimal字符串而不是浮点近似。这里复用第四讲概念，不重复展开金额课程。当前不含税、运费、折扣、汇率，不提供会计或税务结论。approve只接受调查建议，不发起支付。

## 6. 最小实验

Python3.12+，在仓库根目录执行：


预期same_order True、same_item False。示例先核对同采购编号，再发现商品不同，因此不能按相同业务对象比较。此次只有语法审查，预期不等于实际运行结果。

## 7. 故障与选型

金额倍增：先检查一对多连接与重复汇总。找不到单据：检查编号清洗、版本和访问范围，别让模型编造。不同单位仍相减：检查工具输出是否只是标记问题而调用者忽略了。金额对但收货不足：把算术与业务条件分开呈现。审核后状态丢失：内存检查点需按业务换持久存储，不是连接键问题。

数据增长后可使用数据库索引加速查找，唯一约束防止本应唯一的编号重复。但约束必须按正确粒度设计，不能把订单号设为所有收货事件唯一，否则合法多次收货也被拒。加入历史版本、审计、身份权限、备份恢复后才适合跨天多人操作。

## 8. 练习和解释性答案

一：采购编号一致但商品不同，可以比较数量吗？不可以，先解决行级对应关系。

二：两笔收货数量都为4，应删除一笔吗？不能，仅数值相同不是重复证据，要核对事件编号与原件。

三：发票金额正确是否就可付款？不代表，仍需收货、合同、权限和独立付款审批。

四：有数据库join就不需要人工了吗？不是，连接只按规则组合记录，规则和源资料仍可能有错。
