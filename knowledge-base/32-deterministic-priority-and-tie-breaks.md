# 第32讲 多字段排序与并列处理

早班拿到三张返工单。一张已过承诺时间，另外两张等级更高。班组先明确哪种因素优先，再根据时间决定同级先做哪一单。购物结账也有多条规则，但返工还涉及工位、人员和物料。这个例子只演示如何稳定排列待复核工单。

## 排序键怎么比较

排序键是比较一条记录时取出的值。把三个值放在一组，Python 从第一项开始比，相等才看下一项。这里先把严重度取负，使 2 对应 −2，排在等级 1 的 −1 前面。时间统一成 UTC 后直接比早晚，最后比工单编号。

假设 A 的键是 (−1, 14, A)，B 是 (−2, 16, B)，C 是 (−2, 16, C)。B 与 C 第一项相同，第二项也相同，B 因编号更小排前。A 的承诺时间虽更早，严重度规则仍把它排第三。只把 A 的等级改成 2，第一项就与其他两单相同，14 点让 A 排第一。

小题。只用稳定排序，能保证颠倒输入后同级同时间仍有相同顺序吗？不能。稳定意味着相同键保留输入次序。把唯一编号补入键之后，输入次序才不会决定并列结果。

## 最小实验

准备 Python 3.11+，从仓库根目录运行 [实验脚本](examples/priority_tie_lab.py)。

```powershell
python knowledge-base/examples/priority_tie_lab.py
```

脚本先写入三张合成工单。排序函数为每张取负等级、时间和编号。sorted 返回新的顺序，再取出编号打印。第二次反转原列表以检验顺序稳定性，第三次只改 A 的等级。预期依次显示 B C A、B C A、A B C。实际仅完成静态审查，运行输出请自行记录。

## 故障与工程取舍

时间偏移不同的原始字符串不能直接按文字排序。例中 11:00−05:00 与 16:00Z 表示同一时刻。缺时间或缺严重度需要单列，填零会把未知伪装成最低值。重复编号也应回到数据来源核对。

[返工复核 Agent](../examples/rework-priority-review/README.md) 保留每单原始时间与 UTC 时间。工具负责排序和逾期判断，模型读取结果并整理，班组长结合产能审核。当前快照固定，排序规则也固定。真实排程要处理互斥工位和返工依赖，还要记录策略版本。

练习。把 B 的承诺时刻改为 17，C 保持 16，新的顺序是什么？C B A，因为前两张严重度相等，时间在编号之前。把 A 的等级设成未知时，它应进入待补清单，先确认等级再参加排序。交付一张原始值、键、名次的表，并解释这两个变化。
