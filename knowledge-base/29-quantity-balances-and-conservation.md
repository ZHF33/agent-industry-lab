# 第29讲 进出数量与守恒核算

阅读前提是认识整数加减和表格。本课从备件出退库进入数据核算，理解为什么“看起来总量够了”还不能关闭一张申请。配套[备件领用 Agent](../examples/spare-issue-review/README.md)。

## 生活场景与边界
向同事借10支笔，先拿8支，后来还1支，手里从这次借用得到7支，离10支还差3支。这就是有方向的数量计算。类比只说明记录之间的算术关系，不能证明同事实际收到几支，也不能排除漏记。仓库中备件型号、单位和申请编号都必须一致，其他申请的退回不能冲掉这张单的领用。

小练习是想一想，8件轴承和2件密封圈能否满足10件轴承。答案是不能，型号决定分组，数量只能在同一口径中相加。

## 从业务话到公式
先定义符号。R 是申请量，I 是本申请已领出的合计，T 是已退回的合计，N 是净领用，D 是差异。符号不要求背诵，先把它们写在表头。

N = I − T，D = N − R。
D 小于0表示记录显示少领，等于0表示算术相符，大于0表示记录显示超领。T 大于 I 另列异常，可能漏了领出、退回串单或历史起点不同。当前 Agent 不直接处理这些业务原因。

| 备件 | R | I | T | N | D |
| --- | --- | --- | --- | --- | --- |
| BEARING-A | 10 | 8 | 1 | 7 | -3 |
| SEAL-B | 4 | 5 | 0 | 5 | +1 |
| FILTER-C | 1 | 0 | 1 | -1 | -2 |

第一行手算8−1=7，再算7−10=-3。只改变退回量到0，净领用变成8，差异变成-2。这个单变量对照说明退回会减少本申请的净领用。

能否把三种备件的差异相加作为是否合格的唯一判断？不能。即使正负抵消，不同型号仍有各自的短缺。现实还可能存在盒和件的换算、称重误差与在途量，必须先定义合同和计量口径。

## 数据如何变成余额
每条流水保留 record_id、part_id、direction、quantity、unit。record_id 是流水的唯一编号，part_id 是备件编号，direction 的 issue 表示领出，return 表示退回。先校验字段、正整数和单位 piece，再检查编号重复，最后按备件汇总。

应用把方向作为两个独立累计器。领出加到 issued，退回加到 returned，最后减一次。这样报告同时保留两个总量。直接把异常负余额改成0会丢掉“退回超过领出”的证据。

当前规则拒绝布尔值。Python 中 True 可以参与整数计算，但业务数量 True 没有明确含义。重复流水编号也拒绝，不能随意丢弃第二条，因为两条内容可能冲突。若上游需要幂等去重，应先核对同编号内容和可信来源。

小练习是两条不同编号但数量相同的流水是否一定重复。答案是否定的，两次合法领用也可能同量。不能只按金额或数量去重。

## 最小实验与逐段解释
准备 Python 3.11+，打开 PowerShell，进入仓库根目录，使用[课堂代码](examples/quantity_balance_lab.py)。

```powershell
python knowledge-base/examples/quantity_balance_lab.py
```

脚本第一段定义请求量和带方向流水，它们是完全合成的。第二段逐条累计，每读一次流水增加相应的方向计数。第三段计算净量和差异，并把编号列出来。最后一行只显示加入一件退回后差异如何改变，不更新仓库。

```python
issued = sum(row["quantity"] for row in records if row["direction"] == "issue")
returned = sum(row["quantity"] for row in records if row["direction"] == "return")
net = issued - returned
difference = net - requested
```

这段用于解释机制，records 和 requested 由完整脚本提供，片段不能独立运行。

预期首行是 requested=10 issued=8 returned=1 net=7 difference=-3，第二行显示证据编号 M1,M2，第三行 returned=2 difference=-4。本次只做静态语法与逻辑审查，实际输出待读者运行后记录。

## 常见故障与取舍
显示 python 无法识别时，先确认 Python 安装及解释器路径。单位 box 应报输入错误而不是默认按件。重复编号应停止核算等待来源确认。合计为负应保留并追查，不当作允许负库存。

为何本例用整数而不是浮点数？按件计数无需近似小数。称重物料可选择十进制定点并规定精度和舍入。Decimal 也有精度上下文，不能仅靠换类型保证业务口径正确。正式接口需要同时校验单位、允许范围和小数位。

## 在项目中的位置与真实不足
模型通过三个工具获取申请、流水与计算报告。数量函数处于业务适配器和报告之间，人工核查记录来源后才接受报告。它不接数据库、不出库、不代表实物盘点。

当前仅固定快照汇总，没有逐笔时间、期初余额和其他申请关联，无法证明每一时刻都满足物理守恒。相等也可能是漏记领出和漏记退回相互抵消。生产接入应增加导出完整性、申请修订、跨单退料关联和实际盘点证据。

## 分层练习和解释性答案
1. 请求6件，领出7件，退回1件，差异是多少？净量6，差异0；还要检查单位、型号、时间范围和来源。
2. 请求6件，领出0，退回2，是否净领0？应保留-2，差异-8，另标退回超过领出，查漏单或错归属。
3. 何时需要锁或事务？多人并发实际扣减同一库存时，需要数据库原子更新和业务幂等。本课只读快照不涉及该写入链，不能用内存求和代替库存事务。
4. 如何验收本课？交一张逐型号手算表、一次只改变退回数量的对照、两个需人工追查的原因，运行后另附实际输出。
