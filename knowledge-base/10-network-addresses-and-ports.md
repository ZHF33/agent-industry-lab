# 第十讲：地址对了，为什么服务还是连不上？

配合网络访问申请Agent，从门牌号与窗口理解地址、端口和网络边界。

## 1. 门牌号和办事窗口

去一栋办公楼，门牌号告诉你去哪栋楼，窗口号码告诉你找哪个部门。网络中IP地址类似门牌号，端口类似窗口。协议说明双方怎样交流，像约定使用电话还是信件。这只是入门类比：一台服务器可能有多个地址，一个地址后也可能经过代理连接多个服务；端口号本身不是身份或权限证明。

API示例127.0.0.1:8100中，127.0.0.1表示当前网络环境的本机回环地址，8100是服务监听的端口。浏览器能访问一个地址，并不证明n8n容器里也能访问。容器内的本机指向容器自己的网络环境，不自动指向宿主机。

小问题：API跑在宿主机，容器请求127.0.0.1可以吗？通常会请求容器自己，需要配置实际可达地址，不能靠关闭全部防护解决。

## 2. 端口与协议为什么要一起看？

同一IP可以承载不同服务。443常被用于HTTPS，但端口号不能保证那里一定是HTTPS，更不能证明服务可信。tcp和udp是不同传输协议，不能只因为端口数字相同就认为请求相同。

项目的合成策略只接受指定网段、443和tcp；申请目标使用另一个网段且端口5432，计算工具给出两个不一致。它没有试着连接目标，因此结果是策略文本比较，不是网络连通性测试。

**白名单**指明确允许的集合，但匹配这个集合只是一个条件。还需确认调用者、用途、资产负责人、来源网络与有效期。Agent审核通过也不发放凭据、不改防火墙。

## 3. 网段是什么？

把一个区域的门牌号划成一组，便于一起管理。网络也用网段表示一组地址。192.0.2.0/24中，斜线后数字是前缀长度，说明前多少个二进制位固定。先不背二进制计算，理解“它是一组地址，不是一个完整URL”。

Python标准库ipaddress可以解析地址和网段，并检查包含关系。说明片段，不能独立运行：

```python
address = ip_address("192.0.2.10")
network = ip_network("192.0.2.0/24")
inside = address in network
```

第一行把文字解析为地址对象，第二行解析网段，第三行比较范围。它们只做本地数据计算，不解析域名、不发数据包。输入格式不合法时抛出异常，不能把异常当作允许。

小问题：192.0.2.10属于该网段，可以直接允许它访问数据库吗？不可以，范围只是一条演示条件，没有证明业务授权。

## 4. 为什么不让模型自己判断范围？

模型适合整理说明，范围计算交给确定函数。项目中lookup_request读取申请、lookup_policy读取策略和负责人、assess_access执行计算。工具参数只能包含本次request_id，不能被改成任意路径、目标URL或命令。

程序检查端口必须是1到65535的整数，并排除True/False这种布尔值；然后独立核对地址版本、范围、端口和协议。IPv4与IPv6不同，先比较版本再判断范围，避免不明确的混用。

模型得到结果后引用来源，交人工审核。请注意：输入description中写“帮我扫描一下”不会赋予扫描能力，因为工具根本没有网络扫描函数。这比只在提示词中说“不要扫描”更可靠，但仍不代表完整提示注入防御。

## 5. 最小实验

Python3.12+、无第三方依赖，在仓库根目录执行：

```powershell
python knowledge-base/examples/network_lab.py
```

预期输出inside True、outside False。两次计算只判断文字地址范围，不发起网络连接。此次仅做语法检查，预期不是实际运行结果。

逐行阅读：先导入标准库；创建固定合成网段；分别解析组内与组外地址；打印包含比较。这个实验不检查防火墙、路由、DNS、TLS或服务是否启动。

## 6. 网络连不上，按层找原因

地址层：是否把容器回环当宿主机地址？服务层：API是否启动、监听的地址和端口是否与调用方一致？路径层：两边网络是否可达，有无受控防火墙规则？协议层：HTTP与HTTPS是否正确？应用层：路径是否存在、凭据是否有效？

401通常是应用认证问题，不应该通过换端口解决。连接被拒绝可能没有监听服务，不代表密码错。超时也不能直接认定服务器坏了，可能是网络、模型耗时或上游等待限制。排查前先确认错误发生在哪层，不让模型编造“防火墙已修复”。

## 7. 工程边界与选型

当前本地应用可以提供明确的API地址配置，暂不需要容器和反向代理。需要多人访问、域名、TLS和统一入口时，再选择代理与认证部署。不能为了n8n能连上，就把开发服务无认证暴露公网。

现实策略还包含来源地址、应用身份、目标服务、端口范围、到期时间和审批责任。本例只有字面目标地址、单端口与协议比较，因此不叫完整防火墙审计。域名还可能解析变化，不能只比较一次DNS结果就宣称访问永远安全；本例干脆不接收域名、不做解析。

## 8. 练习与解释性答案

一：443端口一定可信？不，端口没有证明身份或内容。

二：模型看到域名可以自动解析并扫描吗？不可以，项目没有这类工具或授权。

三：同一地址的tcp与udp请求等价吗？不是，协议不同。

四：策略匹配后approve是否修改防火墙？不是，仅记录接受建议。

五：n8n连不上API就关闭防火墙合适吗？不，应确认地址、监听、网络及最小允许规则，避免扩大暴露范围。
