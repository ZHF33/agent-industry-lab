# 第31讲 校验位与标签身份

快递员看见一张字迹工整的标签，仍需确认它属于手里的包裹。包装线的扫描复核也有两关。先检查编码本身，再核对它对应哪个箱子。字迹类比只说明检查顺序，扫码软件读取的是字符。

## 怎么从五位得到第六位

校验位是根据正文算出的附加字符。用一套原创课堂规则，把五位字符依次乘 3、1、3、1、3，再相加得 S。取校验位 C = (−S) % 10。这里 % 取除以 10 后 0 到 9 的余数，因此 S + C 是 10 的倍数。文本 00123 得 0 + 0 + 3 + 2 + 9 = 14，补 6 成 20。只把末位改成 5，和变成 19，校验失败。

小题。正文 00124 要补几？S=17，要补 3。若另一个箱扫到 001236，即使能凑成 20，也须按箱核对工单。

## 代码分工与实验

用 Python 3.11+，在仓库根目录运行 [课堂示例](examples/check_digit_lab.py)。

```powershell
python knowledge-base/examples/check_digit_lab.py
```

脚本先将字符逐个转成数并加权。再用输入的末位计算总和。最后分别显示校验是否通过、是否等于工单预期。三个样例预期依次为 True True、False False、True False。实际完成静态检查，运行输出留给读者记录。

在 [包装标签 Agent](../examples/package-label-review/README.md) 中，规则工具在模型整理报告前区分漏扫、格式错误、校验错误与错贴。人工检查扫码来源与实物。数字字段丢掉前导零时，先修复导出类型。全角数字也会被内部规则拒绝，需查扫码配置。

## 能检测什么

此规则能检测任一位数字被替换，因为 1 和 3 都与 10 互质，单个非零差乘权重后无法被 10 整除。交换同权重位置时，加权和保持不变。两个字符的误差也可能抵消。因此在入库或放行前还要比对权威身份。对恶意替换的来源验证需要可信凭据或签名，简单余数不足以承担这一职责。

练习。把 00123 的第 1 位和第 5 位交换后，校验位变吗？这两处权重都是 3，所以不变。写出交换结果及计算，再解释为什么工单核对仍会发现不同。此例的规则为内部教学设计。项目未接设备，也不包含重复扫描事件。
