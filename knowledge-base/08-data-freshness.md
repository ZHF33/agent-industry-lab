# 第八讲：接口成功返回，为什么数据仍然不能用？

面向零基础，配合传感器数据质量Agent。

## 1. 从冰箱里的牛奶开始

你打开冰箱看到牛奶，说明“东西在那里”，不说明它还新鲜。接口返回200也类似：请求处理成功，不等于返回数据及时、完整或符合业务口径。类比边界：数据没有统一保质期，是否新鲜由业务定义。

本例要求60秒更新一次，快照12:03，最近记录12:01，记录年龄120秒。程序标记过旧，但不宣称设备已故障。断更可能来自采集器、网络、存储或设备，需要进一步证据。

小问题：HTTP200能证明传感器正常吗？不能，它只证明某次接口交互成功。

## 2. 三种质量不能混为一谈

新鲜度是最近记录距离观测时刻有多久。有效性是数值与单位是否满足约定。完整性是预期记录是否齐全。例子检查前两类；没有实现完整丢点率分析。最新值999可能很新鲜，却不符合合成数值范围。数据很久没更新也可能最后一个值恰好正常。

**数据契约**是字段与质量规则的约定。本例单位celsius、范围-20到100、间隔60秒，都是演示要求，不是设备安全阈值。不能用这份程序决定机器是否应该停机。

## 3. 计算链：先定义观测，再计算年龄

说明片段，不可独立运行：

```python
age = (snapshot - latest_observed).total_seconds()
stale = age > interval_seconds
```

输入是明确带时区的观测快照、最近非未来记录时间与允许间隔。相减得到时间长度，total_seconds取得完整秒数。最后大于允许间隔才标记过旧。本例恰好60秒不标记过旧；这个边界需要写进业务契约。

未来记录不能参与“最新值”选择，否则错误时钟可能掩盖断更。项目先把未来记录标future_timestamp并排除，再找最新非未来记录。没有记录时age为None，意思是未知，不是0。None自动转0会伪装数据刚更新。

本例latest_age_seconds按时间记录计算，即使该记录值越界，也保留这个年龄；数值问题另列。若业务要的是“最新有效测量年龄”，必须定义有效条件并增加单独指标，不能偷偷换口径。

## 4. 数值和单位怎样检查？

```python
if type(value) not in (int, float):
    # 记录无效值
```

int与float分别是整数和浮点数。不能让字符串“22度”自动混入纯数值字段。这里用准确类型检查，也排除Python的True/False被当成整数。随后判断上下界；NaN（非数字）也不能满足范围比较，最终标记无效。

单位必须等于契约单位。22摄氏度和22华氏度不是一回事；本例不做单位转换，标unit_mismatch交人工调查。缺少单位也是不一致，不能默认猜测。

小问题：空数据应输出健康吗？不应。没有证据就没有健康结论，工具输出stale_or_missing。

## 5. Agent如何使用这些结果？

模型调用契约、读数、质量评估三个工具。程序核对feed_id，计算结果独立放入quality_report。模型解释应检查什么，不能重新编造范围或宣称设备坏了。人工审核只是接受调查建议，程序没有修改阈值、静音告警或操作设备的工具。

当前数据固定合成，不能代表真实工业诊断。后续接监控系统时，需要鉴权、对象访问权限、采集时间和入库时间、持久状态、指标监测与报警责任人。引入Redis并不会自动解决旧数据：缓存可能让过期值看起来一直可读，必须把原始事件时间保留。

## 6. 最小实验

Python3.12+，无第三方依赖，在仓库根目录执行：

```powershell
python knowledge-base/examples/freshness_lab.py
```

预期打印age_seconds 120、stale True。先解析两个明确带UTC偏移的时间，再相减，最后与60秒比较。它只演示新鲜度，不是完整Agent。此次只做语法检查，不编造实际运行结果。

## 7. 故障与工程取舍

旧记录不断显示成功：检查业务年龄而不是接口成功率。未来时间显示负年龄：先校验设备时钟与时区，不要负值归零假装新鲜。新鲜数据却明显异常：单独检查数值/单位。缺记录时输出0：查默认值处理。恢复审核后数字变动：保持原快照，另发新评估才采用新快照。

本例标准库就能完成计算，不必先安装时序数据库。需要长期保留、多设备查询、聚合与历史评估时再评估时序存储。需要通知时再接业务工作流，但通知不等于确认故障。可靠性还要考虑去重、限流、重试和负责人响应，不能每天添加一个库代替业务设计。

## 8. 练习与答案

一：最新记录年龄10秒、值999是否正常？时间新鲜，但数值不符合合成契约，两者分开报告。

二：60秒采一次，120秒没更新是否能确认设备停机？不能，采集链任一环节都可能出问题。

三：拿缓存读取时间当事件时间可以吗？不可以，那只说明缓存刚被读取，不能说明测量刚发生。

四：审核通过能静音告警吗？本例不能。静音是另一种业务权限，需要独立流程。
