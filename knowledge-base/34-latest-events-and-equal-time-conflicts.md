# 第34讲 最新事件与等时冲突

值班簿上，工作台先记录有余料，七分钟后又记录已清。复核时要找最新的现场记录。如果两张单据写着同一时刻，却给出相反结果，仅看哪张纸放在最上面就会误判。纸张类比只能解释顺序。电子记录还有时区、编号和换型范围。

## 从原始事件得到逐点状态

事件是一条带时间的观察。先用工位和检查点限定范围，再把带偏移的时间统一成 UTC，也就是协调世界时。按策略保留满足 start ≤ at ≤ end 的事件。这里 start 是本次换型起点，at 是观察时间，end 是复核截止。起点前的一条已清记录只说明上次现场状态。

对每点保留时间最大的所有事件。集合是只保留不同值的一组数据，拿它统计这些事件出现过哪些状态。集合只有一种状态时，逐点结果就是该状态。集合有两种状态时保留双方证据并标冲突。没有窗口内事件时标缺证。

小题。13:10Z 与 08:10−05:00 是否需要按字符串决胜？二者是同一时刻。偏移为负五小时，转 UTC 要给本地时间加五小时。若状态相反，两条都应进入冲突证据。

## 最小实验

准备 Python 3.11+，从仓库根目录运行 [课堂脚本](examples/latest_event_conflict_lab.py)。

```powershell
python knowledge-base/examples/latest_event_conflict_lab.py
```

脚本先解析三条带偏移的时间。接着用 max 找到最新时刻，再遍历等于该时刻的所有状态并去重。第三步只改变一项，把相反状态改成相同状态。预期先打印 conflict，再打印 clear。倒转输入时，第一次的结果仍是 conflict。实际只完成静态检查。运行后可逐行记录真实输出。

## 故障与工程取舍

没有偏移的时间应回查事件源。直接排序时间字符串会把 08:10−05:00 排在 13:10Z 前面。仅记录一个最新值的字典会覆盖同一时刻的旧值。保留最新时刻的所有记录可见冲突，代价是保存少量额外证据。重复事件编号要核对来源，不能当作独立证据。

[工位换型清场复核 Agent](../examples/changeover-clearance-review/README.md) 已保存逐点状态、纳入及排除证据编号。它采用固定合成快照，缺少事件到达时间和可信的现场物料识别。生产还需确认时钟同步、迟到数据处理、证据来源和工位规程。

练习一。换型起点恰好有一条有余料的记录，截止前没有更新，如何判？起点包含，记录仍有效，标余料。练习二。把冲突中的一条推迟一秒，截止时间仍等于原时刻，结果如何？后一条超窗，剩下原时刻的记录决定状态。若截止也推进一秒，新的最新记录才参与判断。交付一张表，记录原始时间、UTC 时间、是否入窗、逐点结果及证据编号。
