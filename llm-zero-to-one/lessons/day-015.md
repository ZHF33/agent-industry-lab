# 第十五期　文件与文件夹，程序怎样找到一份资料？

前置为[第十四期合成资料](../lessons/day-014.md)。今天从零理解文件、目录与读取，让后面的文档加载和RAG有一个可检查的起点。课堂例子使用一个新建临时目录，保存一条合成JSON，再读回来。

## 1. 同一个文件名为什么会找到不同内容？

用户说“读取sample.json”。电脑里可能在下载目录、项目目录和旧备份各有一份。程序需要知道从哪个位置找。文件名解决叫法，目录层级解决组织和定位。

类比办公室柜子。柜子是目录，文件袋像文件。同名文件袋可以放在不同柜子里。类比边界在于文件还包含编码后的字节、权限与链接等行为，程序打开的真实对象需要按操作系统规则确定。

**文件**是持久存储的一组内容，**文件夹/目录**组织名称和位置。**路径**描述如何定位对象。本课先用项目树建立直觉，下一课再详细比较绝对与相对路径。

## 2. 先画最小目录树

```text
临时课堂目录/
  inputs/
    sample.json
  outputs/
```

inputs存输入样例，outputs留作输出位置。这个命名是课堂约定。文件夹不会自动赋予内容可信度，也不会自动阻止其他程序访问。

sample.json含一个export_id字段，值为EXPORT-DEMO-A。扩展名.json提示我们尝试JSON解析，但文件内容是否符合JSON语法，还需解析器判断。把文件改名为sample.pdf不会自动改变里面的字节结构。

小问题：文件名相同就是同一份资料吗？还需比较位置和内容。需要追踪版本时可以另加版本或哈希，本课先弄清如何读到指定文件。

## 3. 路径对象与真实动作

Python标准库Path表示当前平台的路径。表达式 `root / "inputs"`组合路径，其中斜线运算符由Path定义。它只是生成一个位置表示。调用mkdir才实际创建目录，write_text才实际写内容。

程序动作分步理解如下。

```python
inputs = root / "inputs"
inputs.mkdir()
sample = inputs / "sample.json"
```

输入root来自新建的临时目录。第一行确定子目录位置，第二行创建它，第三行确定文件位置。第三行执行后，文件仍要等待write_text创建或写入。

这个区别会贯穿Agent。模型说“我已经保存”需要执行器真的做过写操作，并有可检查结果。路径字符串或自然语言本身不能证明文件存在。

## 4. 文本怎样进出文件？

**编码**约定文字怎样表示成字节。本课明确使用UTF-8，使中文和其他字符按一致规则读写。用另一种不兼容编码读取可能报错，也可能出现乱码。

```python
sample.write_text(json.dumps({"export_id": "EXPORT-DEMO-A"}), encoding="utf-8")
record = json.loads(sample.read_text(encoding="utf-8"))
```

先将字典序列化成JSON文本，再写入文件。读取时反过来，先得到文本，再由JSON解析器得到字典。读出文本与理解字段是两步。文件存在不代表内容符合预期，JSON合法也不代表export_id真实有效。

同样，模型问答的资料加载也先得到文本与来源信息，然后才进入后续处理。大模型不会因为一份文件存放在电脑上，就自动把它纳入当前上下文。

## 5. 看名称、类型和上级位置

例子读取sample.name得到sample.json，suffix得到.json，parent.name得到inputs。这些是路径结构。调用exists检查对象是否存在，is_file判断是否为普通文件路径，is_dir判断是否为目录。实际访问仍可能受权限或其他进程操作影响。

列目录用iterdir。文件系统返回顺序未必按名称，所以例子用sorted使显示稳定。只要关心“有哪些文件夹”，就先明确是否只列当前层，是否递归，以及是否包括隐藏项目。本课堂只列一个新临时目录的直接子项。

小问题：空的outputs目录会出现在列表里吗？会。目录可以存在而没有文件。

## 6. 最小可复现实验

准备Python3.11+。在PowerShell进入仓库根目录，手动运行[完整文件](../examples/day015_file_tree_lab.py)。

```powershell
python --version
python llm-zero-to-one/examples/day015_file_tree_lab.py
```

程序在系统临时目录创建自己的合成工作区。with块结束会清理该临时工作区。课堂不需要模型或额外依赖。本次只静态检查，预期如下。

```text
folders: ['inputs', 'outputs']
file: sample.json
suffix: .json
parent: inputs
record: EXPORT-DEMO-A
missing exists: False
```

第一行说明建成两个目录。之后三行检查路径结构。record来自真正读回并解析的文件内容。最后一行检查一个尚未创建的合成名字。

若运行权限导致临时目录创建失败，先核系统临时目录权限。FileNotFoundError常来自错误位置或缺文件，JSONDecodeError表示已读到内容但语法不符。把这些错误按阶段区分，可以避免反复改提示词却没修到文件问题。

## 7. 三个单变量练习

先保留程序不变，把sample.json的合成内容换成另一个合法export_id。预期只有record一行变化。再把读取文件名改成missing.json，预期在读取阶段报找不到文件。最后写入普通文字而仍调用json.loads，预期在解析阶段报错。

这三组分别测内容变化、位置错误与格式错误。真实模型能力没有参与，因此不能把结果记为模型问答准确率。
