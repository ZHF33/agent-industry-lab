# Day 029 记录依赖与版本

## 同一张配方为什么做出来不同

两个人按同一张配方做面包，其中一人换了酵母，发酵结果可能改变。程序也会使用他人维护的软件包，这些包叫依赖。版本号用来识别包的一次发布。配方类比提醒我们记录所用材料，实际软件的包名和版本还涉及操作系统、Python 版本和间接依赖，数字越大并不能自动推断适合当前代码。

本课要能说明项目声明了哪些依赖、当前解释器中实际装了哪些版本，以及两种记录各自能证明什么。

## 先把声明写清楚

装配工单 Agent 的 requirements.txt 写着四条直接依赖。直接依赖是项目源码会使用的外部包，包括负责流程、API 校验和服务启动的包。像 langgraph==1.2.14 这一行，左边是分发包名，== 后面固定版本。安装器 pip 接收这样的清单，会同时解析这些包依赖的其他包。后者叫传递依赖，即代码借助一个包又间接用到了更多包。

只固定四个直接包，能限制这四个包的候选版本。若它们对其他包允许版本范围，不同时间安装仍可能选到不同的传递依赖。因此完整记录还应有解析后的清单、Python 版本和平台信息。按需增加哈希可以校验安装文件身份，单独的版本声明也不能证明某段代码已经运行成功。

**小问题**　同事发来一份 requirements.txt，能说明他电脑正用这些版本吗？

**解释**　它说明计划安装什么，实际环境可能没安装、装到另一解释器或被后续命令改动。需在运行程序的同一 Python 环境读取实际版本。

## 从文件到观察结果

课堂脚本读取仓库里的四条清单，按 == 拆成包名和期望版本。这个简短解析器仅适用于本案例这种每行一个固定版本的文件。pip 的正式清单还支持标记、注释、额外依赖等语法，不能拿本脚本解析任意 requirements 文件。

默认模式只展示声明，不访问网络。--installed 模式再用 Python 标准库 importlib.metadata.version 读取环境里的分发包元数据。元数据是描述包身份、版本和依赖的信息。若包未安装，捕获 PackageNotFoundError，显示 missing。这里读取版本无需启动 API 或模型。函数读到的包版本也不能替代功能测试。

**小问题**　若当前安装的是 fastapi 另一个版本，脚本会修复环境吗？

**解释**　它只打印实际版本与相等比较结果，不执行安装。选择何时更新依赖、验证兼容性应由工程流程决定。

## 实验前提和预期

准备 Python 3.11 或更新版本。从仓库根目录运行 [课堂脚本](../examples/day029_dependency_record_lab.py)。默认模式无需第三方依赖。

```powershell
python llm-zero-to-one/examples/day029_dependency_record_lab.py
```

预期打印以下声明。核对的是文件内容，当前课程示例只做静态审查。

```text
direct declarations=4
declared langgraph==1.2.14
declared fastapi==0.142.2
declared pydantic==2.13.5
declared uvicorn==0.54.0
```

若用户已经为案例准备虚拟环境，可手动用该环境的解释器运行 --installed 模式。虚拟环境是单独保存 Python 包的目录，使不同项目的依赖可分别管理。以下命令要求先按案例说明准备 .venv。

```powershell
examples/material-kitting-review/.venv/Scripts/python.exe llm-zero-to-one/examples/day029_dependency_record_lab.py --installed
examples/material-kitting-review/.venv/Scripts/python.exe -m pip check
```

每条 declared 后预期增加 installed 行，版本相同则 matches=True。包缺失则打印 missing。具体实际值取决于使用的环境，本次未读取安装环境或执行上述命令。pip check 检查已安装包的依赖元数据是否满足，仍需另用入口验收行为。若出现文件不存在，先检查案例环境目录。若用一个 Python 安装、另一个 Python 运行，版本记录也会对不上。用 Python 的 -m pip 可把 pip 与当前解释器关联。

## 做一份可交接记录

记录项目提交、Python 版本、平台、直接依赖声明及实际安装版本，再说明功能检查范围。课堂交付可填三栏“包名、声明版本、当前环境版本或尚未读取”，并解释包缺失时该填什么。答案应保留缺失事实，而不能从声明复制一个版本当作实测。

实作边界同样重要。本仓库案例当前只锁定直接依赖，传递依赖仍由 pip 解析。独立虚拟环境便于隔离，完整锁定与安装文件校验有助于进一步复现。后续接模型时，还需记录模型身份和服务接口版本。
