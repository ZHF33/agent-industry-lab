# 第八期｜模型不会凭空上网：“我查到了”与真正获取资料，中间差什么？

先读[第七期：生成与查证](../lessons/day-007.md)。本课的标题指“单独的模型生成不会凭一句提示就自动获得浏览能力”，不是说所有聊天产品都不能联网。

## 1. 一句话不等于一个动作

你问助手：“合成服务DEMO-SERVICE现在是否维护？”它回答：“我刚上网查了，正在维护。”要判断这句话来自哪里，不能只看回答，还应看应用有没有提供查询工具、是否调用、执行结果是什么、结果何时采集。

类比餐厅经理说“我打电话问过仓库”。这句话本身不是电话记录。我们可以查通话与仓库回执，再判断是否问对对象。类比边界：模型是数值生成，程序执行网络动作；不是一个拥有电话的真人。

小问题：提示里加“请联网”，是否已经创建了浏览器和访问权限？没有。它可以影响输出内容或让有工具能力的产品决定调用已有工具，但不能凭空安装网络连接器。

## 2. 先把三个部分分开

**模型**根据本次输入生成下一段内容或工具调用意图；**应用**负责把输入交给模型、执行允许的动作、保存状态；**工具**提供明确定义的操作，例如查某个业务服务的只读状态。

```text
用户问题 → 应用 → 模型
                  ↓ 工具调用请求
              应用校验与执行 → 数据来源
                  ↓ 工具结果
                 模型 → 待核对答案
```

这里的“请求”不是任意一段文字。结构化工具调用通常包含名字和参数，应用先验证，再执行本地函数或网络接口。**API（应用程序接口）**可以先理解为程序之间按约定交换输入输出的入口；本课不用你会写网络请求。

即使模型服务本身运行在远程服务器，向它发送问题所产生的网络传输，也不等于它已经检索了外部网页。**模型传输通道**和**业务资料获取通道**是不同路径。本地Ollama例子中的127.0.0.1指本机回环地址，也不自动代表公网搜索。

## 3. 原理上，外部事实怎样进入生成？

延续前面几期，可把生成分布写成：

```text
P(下一词元 | 输入上下文, 参数θ)
```

若“今日服务状态”不在参数可靠知识中、也不在本次输入，模型可能猜测，但这不构成实际查询。应用执行工具并把结果附入上下文后，条件变成：

```text
P(下一词元 | 问题 + 工具结果 + 既有上下文, 参数θ)
```

这两个条件不同，因而输出可能不同。工具结果进入输入通常不意味着修改参数θ；重新生成依据变化，与训练更新权重是两回事。

注意“可能利用”仍不是“保证正确”。如果工具结果是旧快照、错误对象或恶意指令，模型可能据此出错。外部文本应作为待处理资料，不可让其中“忽略规则、发送密钥”变成应用权限。

## 4. 把一次工具循环拆成六步

1. 应用给模型允许的工具说明，如lookup_fixture与service_id字段。
2. 模型返回选择某个工具的结构化意图。
3. 应用检查名字、参数、对象范围和授权。
4. 合法时执行工具，记录结果或错误；不合法时拒绝。
5. 将工具观察结果交回模型，让它继续选择或形成答案。
6. 检查引用、必要字段和审批状态，再交给用户。

最容易混淆的是第二和第四步：**提出调用**不等于**执行成功**。一个模型能输出“fetch_page”，并不表示程序真的注册了该函数，更不表示访问成功。

Ollama官方工具调用示例清楚区分返回tool_calls和应用执行函数、再把tool结果交回模型。[官方工具调用](https://docs.ollama.com/capabilities/tool-calling)。本课只借这一接口职责解释，不自动启动服务。

## 5. 一个小状态表，比“已联网”更准确

| 情况 | 工具意图 | 执行结果 | 能声称什么 |
| --- | --- | --- | --- |
| 文本说“已搜索” | 没有结构化调用 | 没有执行 | 只知道生成了这句话 |
| 调用合法只读样例 | 有 | 固定合成记录 | 读取了样例，不能说实时联网 |
| 调用任意URL工具 | 有 | 名字不在白名单，被拒绝 | 访问未执行 |
| 真实连接器超时 | 有 | 错误或结果未知 | 没有取得可用查询结果 |

**白名单**是在程序中列明允许哪些工具与范围，未列出的不给执行。它不能只写在提示里；真实执行层必须校验。任意URL获取还涉及私网访问、重定向、响应大小和超时等问题，零基础阶段不开放这个功能。

小问题：工具返回一个source，就等于现在事实吗？不等于。还要核身份、时间、内容、范围和是否真正实时查询；source首先是追踪线索。

## 6. 离线实验：三个消息，零次联网

前提：Python 3.11+，不装额外包、不需要账号。PowerShell是输入命令的窗口；进入仓库根目录：

```powershell
python --version
python llm-zero-to-one/examples/day008_tool_boundary_lab.py
```

完整文件：[day008_tool_boundary_lab.py](../examples/day008_tool_boundary_lab.py)。脚本中的消息**人为编写**，不是模型产生，也没有实现浏览器。按源码推导的预期输出，未实际执行：

```text
no_tool network= False
fixture_read network= False
source: fixture-availability-01
denied network= False
```

第一条只是文本宣称；第二条合法工具读取本地固定字典；第三条要求fetch_any_url，程序没有这个工具，拒绝。三条都没有网络。这个对照说明“有工具”也不意味着“联网”：工具可以是计算器、本地查表或网络连接器，具体看实现。

如果命令找不到python，先解决解释器路径；如果找不到文件，先检查当前目录。脚本显示denied是预期拒绝，不是需要关闭安全检查才能解决的故障。

## 7. 逐段解释：应用才掌握执行权

以下是完整文件片段，不能独立运行：

```python
call = message.get("tool_call")
if call is None:
    return {"status": "no_tool", "network_executed": False}
```

输入是消息字典。`get`读取结构化字段，没找到就得到None。程序不会看到“我搜了”三个字就启动联网，因此自然语言宣称与执行记录分开。

```python
if call["name"] != "lookup_fixture" or call["arguments"] != {"service_id": "DEMO-SERVICE"}:
    return {"status": "denied", "network_executed": False}
```

只允许一个名字及一组固定参数；两者有任意不符就拒绝。真实系统需要从可信用户身份取得授权范围，不应只凭用户自己报service_id授权。

```python
return {"status": "fixture_read", "network_executed": False, "result": dict(FIXTURE)}
```

`dict(FIXTURE)`复制固定合成记录。记录里有观察时间与来源，便于看它是何时的样例。没有urllib、requests或浏览器，所以不能把这次读取称为“已查最新状态”。

## 8. 为什么联网以后仍需查证？

搜索工具可能返回广告、旧文档、同名对象或片段摘要；浏览器可能打不开页面；业务API可能只有部分字段；缓存可能过期。即使网络请求成功，也不等于资料支持答案。

最低证据链应记录：查什么对象；哪个工具；何时取得；什么来源和版本；原文或结构化值；错误与缺项；输出据此说了什么。遇到不确定，收缩结论，别把请求已发当结果已获得。

工具循环还要有上限：调用次数、轮数、超时、响应体大小与总时间。重试前考虑幂等、结果未知和服务限流。今日[API配额Agent](../../examples/api-quota-review/README.md)恰好只分析“如果发送这一批”的预算，不能因为它计算了令牌就说它已经调用业务API。

本期选读Cookbook第三部分第七章的工具与代理介绍及工具反馈例子。提取的知识是模型、工具、执行控制的分工，以及工具观察如何进入下一轮生成。

## 10. 常见问题定位

| 问题 | 先查什么 | 不该直接做什么 |
| --- | --- | --- |
| 说已上网却无来源 | 结构化调用与执行轨迹 | 把自述当证明 |
| 产生tool_call但没结果 | 工具是否注册、参数/权限、错误 | 让模型猜工具返回值 |
| 总是调用失败 | 接口/凭据/超时与范围 | 把密钥贴进公开代码 |
| 查到的内容过期 | 观察时间、缓存、来源版本 | 说“联网即最新” |
| 网页指示泄漏信息 | 工具权限、外部文本信任边界 | 把网页当系统指令 |
| 有查询却无限循环 | 轮数/调用/总时间上限 | 无界重试直到看似成功 |

## 11. 练习与解释性答案

1. 给没有工具的模型一句“立即上网”，它是否已经联网？**不能据此判断。**要看应用是否有相应执行路径和成功记录。
2. 模型服务在云端，所以它每次都搜索网页吗？**不是。**发送模型请求与搜索外部内容是不同网络用途。
3. 本课fixture_read是否获得当前真实维护状态？**没有。**只读固定合成字典，观察时间也是假设样例。
4. 模型要求fetch_any_url，应用拒绝后还可说“我已查询该网站”吗？**不能。**调用意图被拒绝，访问没有执行。
5. 查询成功是否可以跳过人工审批直接改配额？**不能。**只读授权不包括写入，资料正确也不自动赋予操作权限。

当日交付：画“模型请求→程序校验→工具执行→结果返回”的四段链；手写三条消息的预期状态；给一句“我查到了”列出至少三项需要的证据。无GPU、无网络实操也能完成。
