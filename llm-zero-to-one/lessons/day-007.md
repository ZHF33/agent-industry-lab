# 第七期｜生成不等于查证：一句很顺的答案，怎么知道它对不对？

先读[第六期：上下文](../lessons/day-006.md)。今天不要求会数学，不调用模型，以一张概率表和两笔合成金额把“像答案”和“有依据”分开。

## 1. 如果助手把账算得很自信

合成订单有两件商品，3.20和4.30元。助手说：“合计8.00元，已经核实。”句子流畅，格式正确，语气肯定；但你手算就知道总额应为7.50元。

想象一位擅长写发言稿的人：能把话写得自然，不代表他刚才真的拿计算器算过，也不代表他看过订单。类比边界：大模型并不是人在说谎，它是数值模型；出错可能来自信息缺失、推理、解码、工具或应用多个环节。

今天的目标不是得出“模型什么都不会”。模型能做很多有用任务；我们要学会给重要结论安排独立核对路径，不把语气当证据。

小问题：加上“我确定”就提高正确率了吗？这只是文字变化；除非有测量或新增可靠依据，否则不能这么记录。

## 2. 接着上一期，模型到底输出什么？

文字先变成词元，本次上下文经过模型计算，得到下一词元的分数和概率，再由**解码策略**选择下一个词元。选择结果加入前文，继续下一步。

可以简写成：

```text
已有上下文 → 下一词元概率 → 选择一个词元 → 加入上下文 → 重复
```

下一词元在训练数据与当前条件下“可能接在这里”的程度，不是自动连接到现实世界事实表。训练可以让模型学到大量事实规律、运算能力和遵循任务的方式，但不能因此保证每个输出都事实正确。

**查证（verification）**是拿一个可检验说法，与适当证据或规则对照。金额可核算；型号规格要查适用版本资料；客户资格要查订单事实和政策；“这段话支持结论”还要读原文。任务不同，核对方法不同。

## 3. 概率高，为什么仍可能选错？

我们人为设计两项选择，故意让错误答案权重更高：

| 教学候选 | 人工权重 | 与3.20+4.30是否一致 |
| --- | ---: | --- |
| 8.00 | 0.8 | 否 |
| 7.50 | 0.2 | 是 |

这不是某个真实模型的实测分布。每项代表完整候选答案，不是说“8.00在真实分词器中一定是一个词元”。

**贪心选择（greedy selection）**每步选当前概率最大的候选，在这张表里会选8.00。降低随机性无法自动创造算账证据；稳定选错仍然是错。实际模型往往处理许多词元，逐步选最大也不等于找到整个句子概率最高的序列。

如果按这张表随机抽取一次，抽到8.00的概率为0.8。它不是“8.00在现实中有80%机会正确”：真实总额已经由输入确定。这张表的含义是选择分布，不是事实概率。

小问题：如果连续重复三遍8.00，算三个独立证明吗？不是。可能同一模型、同一错误条件被重复使用；重复文字不提供新证据。

## 4. 用温度公式看清它改了什么

**温度（temperature）**是一些采样方法中调整分布陡峭程度的参数。给定一组分数z和正温度T，可以写：

```text
p(i) = exp(z_i/T) / 所有候选exp(z_j/T)之和
```

`exp`是指数函数，i、j只是候选编号。你无需现在计算指数；先看结论：较小的正T通常让已有最高分候选更突出，并不会去读订单重新求和。

为了便于手算，从人工概率0.8和0.2出发，采用等价的幂变换：当T=0.5，分别平方再归一。

```text
0.8² = 0.64，0.2² = 0.04
错误候选的新概率 = 0.64 / (0.64+0.04) ≈ 0.9412
正确候选的新概率 ≈ 0.0588
```

分布更集中到了错误候选。本段只说明“降温不是事实修复器”，不是建议所有任务用高温。温度为0时很多接口采用特殊解码约定，不能直接把T=0代入除法公式；设置是否生效也取决于是否采样及服务实现。

[Hugging Face生成策略文档](https://huggingface.co/docs/transformers/en/generation_strategies)区分贪心与采样，本课不复制它的下载模型示例，也不承诺某接口默认值适用于所有产品。

## 5. 独立计算，比重复问“你确定吗”多了什么？

两笔价格都来自输入，要求加法，规则明确：

```text
3.20 + 4.30 = 7.50
核对：声称的8.00 == 算出的7.50？否
```

我们把生成建议与确定性工具分开。**确定性**在这里指同样合法输入按同一规则给同一结果，不表示工具永远无错：若订单抄错、币种混合、漏了一项，再精确的加法也会核错业务。

**Decimal**是Python标准库提供的十进制数类型；从价格字符串构造，避免先把价格当二进制浮点近似再转换。本课只演示相同币种、两位小数合成价格求和；税费、折扣、汇率、舍入规则都须另定义。

小问题：计算器返回7.50，能证明实际付款也是7.50吗？不能。它验证输入加法，不查询支付系统，也不核对输入是否完整。

## 6. 离线实验：人工生成权重与核算对照

前提：Python 3.11+，无需GPU、账号或额外依赖。在PowerShell进入仓库根目录，输入：

```powershell
python --version
python llm-zero-to-one/examples/day007_verification_lab.py
```

完整文件：[day007_verification_lab.py](../examples/day007_verification_lab.py)。这是可独立运行的标准库脚本，不是真实语言模型；我们没有在本机执行它。按源码推导的预期为：

```text
toy_choice: 8.00
exact_total: 7.50
claim_matches: False
corrected_matches: True
invalid: Finite non-negative prices and finite claim required
```

第一行故意选权重最大项；第二行独立求和；第三行比对；第四行换成正确声称再对照；最后用NaN测试错误输入识别。NaN表示“不是一个数”，不能当作普通价格参与核算。

命令找不到python先解决解释器路径；找不到脚本检查目录；程序输出False表示声称不匹配，不是脚本故障。

## 7. 逐段解释代码

以下为完整文件片段，不能单独运行：

```python
selected = max(WEIGHTS, key=WEIGHTS.get)
```

输入是候选到权重的字典。`max`按指定规则找最大项；`WEIGHTS.get`告诉它比较权重，返回候选文字8.00。这模拟选择，不训练模型。

```python
values = [Decimal(x) for x in prices]
expected = sum(values, Decimal("0"))
```

输入是价格字符串列表。逐项转十进制数，再从十进制0开始求和。没有网络、订单库或付款动作。随后比较`claim == expected`得到布尔值True或False。

```python
if not values or not all(v.is_finite() and v >= 0 for v in values):
    raise ValueError(...)
```

这段为简化示意，完整文件还核对声称是否有限。`all`要求每项都满足；`is_finite`排除NaN与无穷。先校验再求和，避免坏输入产生貌似正式的报告。

当前脚本对真实金额精度、上限、币种和完整性限制仍不足，不应直接成为结算组件。它的职责是解释生成选择与规则核对的分工。

## 8. 有引用，就算查证了吗？

今天的客服Agent会返回合成知识段落。假设资料原句要求订单日期和损坏证据，模型却写“所有破损杯子直接退款”，即使后面挂着真实source ID，也可能超出了原文。

需要拆成四层检查：来源存在；引用文字来自该来源；文字支持当前说法；来源适用于这个对象和时间。**蕴含关系**可直观理解为“证据是否足以推出这条结论”。匹配关键词不够，来源ID存在也不够。

当证据缺失，正确行为可能是“不足以判断，请补订单日期”，而不是选择概率更高的“可以退”。检索增强能够补充依据，但仍需要评估与权限边界。

## 9. 上游教程，也要查证

本期选读Cookbook“提示原则”里的结果核对和局限性内容：具体思路是先取得可核查依据、再审结论，认识到模型可能补出未经证实细节。我们用原创金额与合成杯子资料说明，不搬运原文案例。

其中使用真实品牌/型号来举“虚构产品”的例子，本课不继承其存在性判断；那需要另外查当时产品资料。教材里一句“这是编造的”也不是今天就能复用的事实证据。后续教学同样要核实来源，不因为开源收录就自动正确。

分隔符能组织资料，但不是安全边界；要求模型自己检查可改善某些任务，却不等于独立验证。我们不要求公开模型内部思维，交付可检查的输入、计算、引用与判定即可。

## 10. 常见误区与排查

| 误区 | 为什么不足 | 可检查做法 |
| --- | --- | --- |
| 低温就不会错 | 调整选择不等于新增证据 | 固定证据和核算规则后评估 |
| JSON合法所以内容真 | 语法与事实是两层 | 校验字段含义、来源和业务范围 |
| 同模型再答一次算复核 | 错误可能相关、没新信息 | 加计算器/原文/权威记录或人工 |
| 带source就全部可信 | 引用可能不支持说法 | 逐条对照原句和适用条件 |
| 计算对等于业务对 | 输入也可能错漏 | 核币种、对象、完整性和时间 |
| 不知道就是失败 | 资料不足时拒绝编造更合理 | 说明缺项并指向补充证据 |

## 11. 练习与解释性答案

1. 把权重改为正确答案0.9、错误0.1，贪心会怎样？**选正确候选。**但这是改了人工表，不是证明现实模型全部可靠。
2. 对0.6和0.4做T=0.5的幂变换，前者变多少？**0.36/(0.36+0.16)≈0.6923。**概率更集中，不新增事实。
3. 两件价格3.20、4.30，助手说7.50，能批准退款吗？**不能。**加法通过不等于政策或订单资格通过。
4. 检索零命中，模型凭常识答“30天内可退”，能否发布？**不能。**缺当前业务证据，必须说明不足并转人工。
5. 候选引用要求检查source出现，是否完成蕴含验证？**没有。**只能挡住一部分无来源输出，仍需审查原文是否支持结论。

当日交付：手算7.50；解释0.8不是事实正确率；给一条合成客服建议写“说法→依据→独立核对→缺失项”。不要只交一句“模型会幻觉”。
