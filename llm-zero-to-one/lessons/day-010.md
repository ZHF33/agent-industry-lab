# 第十期｜什么时候应该拒绝自动化？把“能回答”与“能执行”分开

前置：[第九期工具契约](../lessons/day-009.md)。本课不讨论抽象口号，而用合成数据访问申请，讲清信息、授权、人工审核和执行后果怎样决定流程。

## 1. 答案很完整，也可能该停下来

有人说：“昨天批准过数据集A的只读申请，现在帮我直接开权限。”模型也许能理解这句话、查到批准记录、生成正确操作格式。但申请可能已改版，批准可能过期或撤销，当前操作者也未必拥有授予权限。

类比熟悉路线不等于拿到车钥匙、驾照和本次出车许可。类比边界：真实权限不是一张纸能概括，程序还要验证身份、资源和动作；不能仅凭用户自述或模型自信。

本课的**拒绝自动化**可以是“停止执行并补证”“转给有权限的人复核”，不必拒绝所有帮助。仍可整理材料、指出缺项、起草建议，但不能假称动作完成。

小问题：拒绝执行与拒绝解释是同一回事吗？不是。可以解释为何无法执行、哪些条件缺失，并给明确下一步。

## 2. 四个问题，依次判断

**证据完整吗？**相关事实是否取得、对象匹配、时间适用，矛盾是否解决。**有授权吗？**由可信身份和业务规则决定该人/程序能否对该资源做该动作。**后果可恢复吗？**出错是否能用明确步骤恢复，恢复是否有成本。**规则要求人工吗？**有些动作即使材料完整，也必须由具名负责人审核。

“可恢复”不是一句“可以撤销”：恢复可能需要备份、重新发消息无法收回、权限期间资料已经泄漏也不能靠撤权抹掉影响。必须按真实业务评估，本课仅用布尔标记做课堂简化。

四个问题没有让模型独自决定真实权限。模型可以帮助提取信息、解释原因；执行层必须拥有可检查且可信的事实和授权来源。

## 3. 原理：语言概率不提供业务授权

前几期把生成写为`P(下一词元 | 上下文, 参数θ)`。这个式子说明输出受输入和参数影响，不是权限授予规则。

哪怕文本“已批准”的生成概率很高，也不等于身份系统验证成功。模型给出的0.95自信，若没有校准与评估，也不能直接当“执行正确率95%”。**校准**是预测置信度与实际正确频率之间是否匹配的一类评估概念，本课不做它的实验。

执行门可以写成逻辑条件：

```text
证据足够 且 可信授权通过 且 业务规则允许该自动路径
```

这里“且”表示每项都要满足，不能用“模型能力强”抵消缺授权。若任务还要求人工，程序必须停在审批状态，而不是让模型自己说“负责人应该会同意”。

## 4. 手推一张路由表

**路由**就是把不同输入送到不同后续处理，而不是在网上选道路。

| 场景 | 结果 | 仍可提供的帮助 |
| --- | --- | --- |
| 少订单/申请关键事实 | 补证 | 列出缺哪些资料 |
| 事实全但无授权 | 拒绝执行 | 解释授权范围与找谁处理 |
| 已授权但不可轻易恢复 | 转人工 | 整理影响与回滚条件 |
| 规则要求人工 | 转人工 | 形成带证据待审建议 |
| 所有简化条件满足 | 有界自动化候选 | 继续进入真正执行检查 |

最后一行仍不是“已经执行”。课堂布尔标记无法替代真实输入来源、权限、限额和执行原子性。本课故意把输出叫candidate，防止教学代码越权承诺。

如果同时少证据又无授权，脚本先返回补证，是演示的优先级，不是建议绕过安全拒绝或向无权用户索取敏感信息。真实系统应先完成身份与资源可见性控制，再在允许范围内反馈缺项。

## 5. 用数字看“准确率高”为什么仍不够

假设一个合成分类器在100条只读分流任务中错2条，则这份样本的错误率是`2/100=2%`。它不是任何未来任务的保证，也不是授予写权限的依据。

同样2次错误，若只是把咨询分错队列，处理成本可能有限；若错误发出不可撤回业务指令，后果不同。需要把**错误频率**、**错误代价**和**自动执行范围**分开评估，不只比较一个准确率。

没有真实实验就不能写“系统准确率98%”。这组数字是纸笔假设，目的是说明为何不同动作需要不同容错与审核策略，而不是为今天Agent打分。

练习：100条样本错1条能直接证明适合自动开权限吗？不能。还缺样本覆盖、权限验证、错误后果、分布变化和业务要求。

## 6. 离线实验：把停止路径写成程序

前提：Python 3.11+，不需要GPU、模型、网络或额外依赖。Windows打开PowerShell，在仓库根目录输入：

```powershell
python --version
python llm-zero-to-one/examples/day010_automation_gate_lab.py
```

完整文件：[day010_automation_gate_lab.py](../examples/day010_automation_gate_lab.py)。输入标记是人为合成，不是系统真的验证过权限。按代码推导的预期，未实际执行：

```text
missing: request_evidence
unauthorized: deny_execution
irreversible: human_review
review_policy: human_review
bounded_candidate: candidate_for_bounded_automation_not_execution
invalid: Boolean flags required
```

最后一条把字符串yes当布尔输入，按契约拒绝。脚本没有任何发消息、写库、开权限函数，因此无论返回哪种路由，都没有实际执行。

## 7. 分段读代码

下列片段来自完整文件，不可单独运行：

```python
if any(type(value) is not bool for value in flags):
    raise ValueError("Boolean flags required")
```

**布尔值**只有True/False，表示本课的真/假条件；`any`表示只要有一项类型错误就拒绝。不能用非空字符串“no”冒充False，因为很多程序语言会把非空字符串当真。

```python
if not evidence_complete:
    return "request_evidence"
if not authorized:
    return "deny_execution"
```

第一段是输入是否足够的教学判断，第二段是授权标记。动作是返回状态文字，不是停止一个已经启动的业务进程。真实应用要把返回状态接到控制流，不能只打印deny但继续执行。

```python
if review_required or not reversible:
    return "human_review"
```

`or`表示两项任一满足就转人工；本课保守地把不可恢复动作送审。生产还要细化何种人工、权限、审批绑定、截止时间、冲突和失败恢复，不能复制四个if就声称安全系统完成。

## 8. 人工审核也有生命周期

人审不是永久通行证。批准应绑定提案和范围，真实身份需认证，到期/撤销/已经使用等状态必须在执行端核对。人的决定也可能错误，所以仍需原子条件、记录和后续核查。

今日[批准时效Agent](../../examples/approval-expiry-review/README.md)处理的正是“记录里approve还适不适用”。它只读取合成证据并报告阻断原因；接受这份报告，不会给真实申请开权限。

LangGraph的interrupt和Command提供暂停/恢复机制，不能自动提供业务身份、签名和审批有效期。[官方interrupt文档](https://docs.langchain.com/oss/python/langgraph/interrupts)。工程中应把“等到人回复”与“回复有权且仍适用”分别检查。

## 9. 如何表达一个有用的停止？

可采用“当前能确认的事实→缺失/冲突条件→本次停止的动作→允许的下一步”。例如：合成批准截止12:00:30，审核时刻已到边界；停止权限授予；请有权负责人基于当前申请重新审核。

不要编造风险以拦住所有任务，也不要在条件已足够、用户已授权的低影响范围内反复索取同意。审核点来自真实业务规则、权限和后果，保持具体；“请确认一下”不能代替把提案准备清楚。

本课不要求模型展示内部思维。需要的是可检查的证据、判定条件、缺项和状态转换。若遇到缺环境，给可运行代码、前提和逻辑记录，但不能把未执行写成成功。

## 10. 教材中的知识怎样转成工程规则？

本期选读Cookbook提示原则中的结果核对与局限性：提取“不要把流畅文字当独立事实核验”的知识，再扩展为本课执行门。四标记路由是我们的原创工程教学，不声称上游提供同样算法。

提示可以要求资料不足时承认不知道，但程序仍需校验。分隔符帮助组织输入，不能替代权限控制。温度低可以改变生成分布，也不能补出缺失授权。上游真实产品例子的存在性判断不在本期继承。

## 11. 常见故障与练习

| 故障 | 核对方向 |
| --- | --- |
| 明明deny却执行 | 返回状态是否真的控制执行器 |
| review后直接继续旧提案 | 是否核当前版本/范围/有效期 |
| 模型自信就放行 | 信心是否被误当认证或证据 |
| 失败后不停重试 | 是否有截止时间/幂等/人工出口 |
| 所有任务都转人工 | 是否把具体规则误写成无条件拦截 |

1. 证据完整但缺授权，怎么办？**拒绝执行**，可在允许可见范围内解释原因，不代替管理员授予权限。
2. 只读查询是否完全无风险？**不是。**仍有隐私、访问范围、费用与负载，需要按实际场景控制。
3. 所有标记通过，脚本做了业务动作吗？**没有。**返回候选路由，不具备执行器。
4. 人说approve但批准过期，能继续吗？**不能直接继续。**核业务规则，获取当前适用授权，而不是偷偷续期。
5. 100条错1条就可生产自动化？**不足以判断。**要看覆盖、代价、权限与业务验收，不只看比例。
