# 第十一期｜把“帮我优化业务”写成一个可交付任务

前置：[第十期自动化边界](../lessons/day-010.md)。本期目标：给出一张别人能够照着实现和验收的任务卡，区分业务目标、模型工作、工具计算和人工责任。我们不训练模型，不需要GPU。

## 1. 一句“优化冷链”，为什么还不能开工？

有人说“给我做一个智能冷链助手”。这句话表达方向，却没有说明谁用、目前哪里慢、能看哪些记录、最终要交什么、能否操作设备、什么结果算成功。

类比请厨师“做得更好吃”：可以指口味、速度、份量或成本。同样，模型可能把优化理解成写建议，开发者可能理解成做看板，运营可能期待自动调温。类比边界：软件还涉及接口、状态与访问范围，不能仅靠多写形容词形成工程契约。

**业务目标**是想改善的结果，例如减少收货员逐条核查混合单位温度记录的工作。**任务**是明确条件下的一项可检查工作，例如针对指定运单和固定窗口，列异常点、未知间隔和待人工检查项。业务目标可以长期持续，今天交付的任务必须有边界。

小问题：“提升效率30%”算今天的验收吗？如果没有基线、测量方法和真实比较数据，它只是目标，不能写成已经实现的成绩。

## 2. 先确定谁要作什么决定

本期只用合成工业材料，不涉及真实产品质量结论。目标用户是收货运营，当前决定是“哪些证据需要人复核，缺什么记录”，不是“货物是否安全、是否立即放行”。

为什么先写决定？同一份遥测可以用于异常排查、质量调查、索赔或设备维护；这些任务所需证据和权限不同。数据很多不代表任务明确。

把“自动处理一切”缩为“只读证据分诊”，能在一个MVP中交付完整流程：读输入→查资料→核算→形成建议→人工接受/拒绝。**MVP**指最小可用版本，功能范围小，但选中的流程应闭合，不是一个只有标题的空壳。

## 3. 用六个问题形成任务卡

| 字段 | 要回答的问题 | 本期合成例子 |
| --- | --- | --- |
| user | 谁在使用 | 工业材料收货人员 |
| decision | 用户要判断什么 | 异常证据与待补记录有哪些 |
| inputs | 允许读取什么 | 运单ID、带单位/时刻的读数、固定窗口、合成阈值 |
| outputs | 交付什么 | 异常点、估算/未知时长、来源与待审建议 |
| constraints | 哪些限制必须遵守 | 只读、不放行、不调设备、不作质量认证 |
| acceptance | 怎样判断交付符合约定 | 指定样例和错误分支，有明确预期 |

**输入**是本次工作的材料，**输出**是交付物，**约束**是不能违背的条件，**验收**是核对结果的方法。六字段是我们为课堂设计的表，不是所有公司的统一行业标准。

卡里每项尽量可以检查。“回答专业一点”没有解释标准；“标出原始读数、单位、来源与未知区间”就能核对。不能把“让模型更聪明”当作输入，也不能把“输出JSON”当作唯一正确性标准。

## 4. 原理：任务卡怎样影响模型，又不能做什么？

先回到生成机制：模型根据当前输入及参数，得到下一词元的分布。把任务写清楚，改变的是条件输入，帮助减少多种解释之间的歧义；没有因此更新模型参数，也没有自动增加权限。

原来只有“优化冷链”，可接受解释很多。加入“指定运单、只读、列证据、转人工”，就给生成提供更明确的目标。这里是机制解释，不声称已经实验测到效果提高多少；模型仍可能忽略条件或生成错误。

可以把本期任务过程记成：

```text
T = (U, D, I, O, C, A)
```

T表示一张任务卡，U用户、D决定、I输入、O输出、C约束、A验收。这只是把六项放在一个有顺序的组合中，方便核对，不是模型训练公式。若没有可信输入I，再清楚的O也不能凭空产生事实。

还要区分三种层次：提示里写“只读”；程序只提供读工具；身份系统限制真实账户权限。第一层说明意图，后两层才实际限制执行能力。不能因为提示中出现C，就宣称已实现全部安全约束。

## 5. 把任务拆成确定计算与模型判断

本期50°F换成10°C应交给可检查公式，不让语言模型凭感觉回答。对象匹配、字段类型、间隔长度也应有程序校验。模型更适合在受限证据中选择查哪个工具、读取结果、组织异常解释与待检查事项。

本仓库[冷链温度异常Agent](../../examples/cold-chain-excursion-review/README.md)提供三工具：查运单/政策、查读数、计算异常。模型可以选择工具及顺序，程序控制范围、预算和必须取得的证据，再把结果交人审核。

这解释Agent与固定规则脚本的差异：脚本按预设顺序完成同一计算；Agent由模型选择下一步并看到工具反馈。两者都需要输入输出契约。把一个if脚本改名Agent，不会增加模型决策循环。

小问题：模型输出“已经放行”，但程序没有放行工具，能算执行成功吗？不能。自然语言不是执行证据，系统应保留真实工具轨迹并避免这种误导。

## 6. 用一个数字例子写验收

合成窗口12:00–12:20，共1200秒。采样值依次4°C、50°F、10°C、4°C，时刻为12:00、12:05、12:10、12:20。合成范围2至8°C，最长可估算间隔300秒。

手推：50°F=(50−32)×5/9=10°C。第一段按左值4°C保持估算300秒在范围内；第二段按10°C估算300秒超上限；第三段600秒超过间隔限制，全部未知。

验收不写“分析准确”，而写：保留两个异常采样点；估算超上限300秒；未知600秒；总时间分组为1200秒；没有放行动作。随后再加反例：把50°F改成10°C，物理值相同，计算结果应相同；没有unit时拒绝转换；缺测不能被补成正常。

**单变量对照**就是尽量只改变一个条件，观察该条件是否产生预期影响。本期是源码推演与验收设计，未运行模型或这些对照，不记录虚构的实测结果。

## 7. 离线实验：自动发现任务卡缺字段

环境：Python3.11+，无额外依赖、模型、网络或GPU。在PowerShell进入仓库根目录：

```powershell
python --version
python llm-zero-to-one/examples/day011_task_card_lab.py
```

完整文件：[day011_task_card_lab.py](../examples/day011_task_card_lab.py)。按源码推导的预期，未执行：

```text
vague: ['inputs', 'outputs', 'constraints', 'acceptance']
complete: []
bad_list: ['inputs']
```

第一条卡只有用户和一句方向，缺四项。第二条结构完整，所以错误列表为空。第三条把输入列表写成字符串，程序拒绝这种结构。

注意：空列表不是“任务一定合理”。如果把acceptance填成“必须永远正确”，格式检查也可能通过；语义需要人核任务可行性、真实数据来源与验收方法。本脚本不调用任何业务工具，不能当任务执行器。

## 8. 逐段读代码

以下是完整文件片段，不可独立运行：

```python
FIELDS = ("user", "decision", "inputs", "outputs", "constraints", "acceptance")
```

这是允许字段的集合式清单，实际类型为有顺序的元组；使用英文键便于程序引用，不要求读者记住语法才能先写中文任务卡。

```python
value = card.get(field)
```

card是键值对象，`get`按字段取内容，缺失时返回None。程序随后检查前两项是非空文字，后四项是至少一条非空文字组成的列表。**类型**说明数据形式，字符串和列表用途不同，不能只看屏幕上都显示中文就混用。

```python
if not valid: errors.append(field)
```

不符合结构就把字段名记入错误列表，不是让模型自己补齐真实业务信息。程序可以提供模板，但用户、授权和真实产品标准不能靠默认值伪造。

遇到文件找不到先核工作目录；结果显示inputs时先核该字段是否列表；若格式过关却仍无法实施，回到语义和数据可得性检查，不要继续扩大模型输出长度。

## 9. 参考资料的知识怎么用到本课？

实际选读Cookbook C1提示原则的1.2结构化输出、1.3条件检查、2.1步骤指定。我们提炼成三个教学问题：交付物能否按字段核对；缺前提是否有明确出口；大任务能否拆成可检查动作。六字段任务卡、合成温度例子和校验脚本是原创扩展，不是教材的原作业。

结构化输出只使结果易处理，不能证明值真实；提示要求检查条件，也不能代替服务端校验；步骤拆解是工作安排，不需要索取模型完整内部思维。分隔符帮助组织材料，不构成权限隔离。不能照搬上游过强的安全表述。

## 10. 常见偏差、工程取舍与练习

| 偏差 | 改进方式 |
| --- | --- |
| 卡里只有技术栈 | 先写使用者与决定，再选工具 |
| 数据写“所有资料” | 限定对象、时间、字段、来源与访问范围 |
| 验收只看文字是否好读 | 增加可手算例子、错误分支与执行边界 |
| 每个任务都堆四种框架 | 根据状态、触发、知识和适配需求选择 |
| 草稿格式通过就宣布业务通过 | 分开结构、语义、静态检查、运行与业务验收 |

1. “做个RAG”是否已定义任务？**没有。**技术名缺用户、问题、资料、输出与验收。
2. “不准写库”只写在提示够吗？**不够。**工具白名单、账户权限和执行端控制需要落实。
3. 今天要用Dify吗？**这个小案例无需。**固定遥测核算不依赖运营知识库；LangGraph管循环，n8n管入口，按需要再扩。
4. 脚本返回[]能否证明效率提高？**不能。**只是任务卡结构符合本课堂规则；效率需实际测量。
5. 改一个真实产品阈值就能投产吗？**不能。**还需可信来源、校准、产品适用规则、权限、持续运行与业务验收。
