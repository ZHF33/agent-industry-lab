# 第十六期　同一条相对路径，为什么换目录就找不到了？

前置为[第十五期文件与文件夹](day-015.md)。本期解释路径如何依赖起点，学会分别定位“脚本在哪”“命令从哪执行”“资料根目录在哪”。课堂只计算路径文字，不需要GPU、模型或网络。

## 1. 收到“往前走十米”，你会从哪出发？

相对路径像“从当前位置往前走”，需要起点。绝对路径像一个明确地址，带系统起始位置。生活类比的边界在于操作系统还有驱动器、挂载和链接。路径明确只能帮助定位，读取权限与内容版本仍需核查。

`inputs/sample.json`是一条相对路径。起点若为/demo/project-a，就定位到/demo/project-a/inputs/sample.json。起点换成project-b，目标跟着变化。字符串没变，解释它的环境变了。

小问题：脚本保存在project-a里，从project-b运行，Path("inputs/sample.json")默认从哪里找？通常按进程当前工作目录project-b解释，而非脚本保存位置。

## 2. 当前工作目录怎样参与读取？

**进程**是正在运行的程序实例。每个进程有当前工作目录，命令行中进入某目录后启动程序，程序通常继承该目录。Path.cwd()可读取它。执行脚本时，脚本路径与当前目录可以不同。

例如在仓库根目录执行python tools/read.py，read.py在tools里，但默认相对文件仍从仓库根目录定位。如果程序需要跟随脚本位置，应显式从脚本文件位置推导。项目里某些练习用Path(__file__).resolve().parents来找到示例目录，这正是为避免依赖启动位置。

更复杂应用可以接受配置的资料根目录。入口检查配置后，把确定的根传给后续模块，使同一条任务在不同启动方式下行为清楚。不要依赖开发者电脑上碰巧存在的另一个同名文件。

## 3. 绝对路径长什么样？

POSIX风格常从/开始，比如/demo/shared/sample.json。Windows常有C:/这样的驱动器和根。Windows还有网络共享与驱动器相对形式。跨平台处理时需要按实际语义判断，不能只查是否出现冒号。

本期课堂统一使用PurePosixPath，明确只做POSIX路径文字运算。Pure类不访问操作系统，因此Windows电脑也可以推演这些例子。实际程序访问本机文件可用Path。绝对路径在另一台电脑上未必存在，分享项目应尽量配合配置和项目根定位，避免硬编码个人目录。

## 4. 从组合运算推导目标

代码片段如下。

```python
relative = PurePosixPath("inputs/sample.json")
base = PurePosixPath("/demo/project-a")
target = base / relative
```

relative不带根，base带根。斜线运算把它们组合为/demo/project-a/inputs/sample.json。此时只得到位置表示，尚未读文件。

再看一个容易出错的变化。

```python
absolute = PurePosixPath("/demo/shared/sample.json")
target = base / absolute
```

右边已经带根，组合结果采用右边的绝对位置。它不会变成/demo/project-a/demo/shared/sample.json。因此若外部输入被当作必须留在项目内的相对路径，就需要先校验路径契约。本课展示语义，不能将简单拼接当安全目录隔离。

## 5. 同名文件如何排错？

先记录程序实际工作目录与目标位置，再确认文件存在、类型正确、可读取，最后检查编码、格式和版本。这样能把“找不到文件”“读错同名文件”“内容解析失败”分成不同阶段。

真实用户资料可能出现在路径里，排错输出只保留必要部分。公开练习使用/demo这样的虚构位置。不要为了演示路径在仓库里粘贴个人账号、客户目录或密钥位置。

结合[生产任务依赖Agent](../../examples/task-dependency-review/README.md)，当前数据由合成代码内置。若将来从文件加载生产计划，入口需要明确资料根、计划ID与版本，并在读取后校验依赖字段。路径定位与模型解释分别负责不同环节。

## 6. 最小可复现实验

环境Python3.11+、无额外依赖。在PowerShell进入仓库根目录，运行[完整文件](../examples/day016_path_base_lab.py)。

```powershell
python llm-zero-to-one/examples/day016_path_base_lab.py
```

源码推导的预期如下，本次未执行。

```text
/demo/project-a/inputs/sample.json
/demo/project-b/inputs/sample.json
absolute: True
join absolute: /demo/shared/sample.json
same relative text: inputs/sample.json
```

前两行只改变base，目标随之改变。第三行判断绝对路径。第四行显示绝对右操作数覆盖起点。最后一行说明原始相对路径没有被组合运算原地修改。

如果找不到课堂脚本，先确认命令执行位置；若导入PurePosixPath失败，确认使用标准Python3。课堂计算不检查这些虚构路径是否存在，所以程序输出路径也不代表文件已创建。

## 8. 常见错误与练习答案

| 错误 | 优先核查 |
| --- | --- |
| 脚本迁移后找不到资料 | 路径起点、工作目录、项目根配置 |
| 组合后跳到另一位置 | 右侧输入是否已经是绝对路径 |
| 同事电脑运行失败 | 是否硬编码了本机绝对位置 |
| 输出路径却没有文件 | 是否只计算Path，尚未调用创建/写入 |
| 文件存在但内容不对 | 同名位置、资料版本和解析契约 |

1. 相对路径是否总更安全？不自动成立，还需对象范围、链接与访问权限检查。
2. 绝对路径能否保证文件可读？还需存在性、类型与权限，环境也可能变化。
3. 为什么把工作目录与脚本目录分开？它们可以不同，默认相对读取通常由前者决定。
4. 改变base会改变relative本身吗？这个例子产生新路径对象，relative保持原值。
5. 哪些路径适合公开例子？独立合成位置，避免携带真实用户或业务信息。
