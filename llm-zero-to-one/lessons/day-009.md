# 第九期｜为什么需要工具？把“会表达”接到“可计算、可约束”的工程能力

建议先读[第八期](day-008.md)理解模型、应用和工具执行分工。

## 1. 工具不只是帮模型补一道算术

合成工单提案基于revision=4，当前快照revision=5。助手需要回答三类问题：用户想做什么；版本是否相同；此刻是否允许实际修改。第一类适合语言理解和解释，第二类有明确相等规则，第三类还要业务状态、身份授权和提交时的原子条件。

让模型全部靠文字答，可能把这三层混在一起。让工具做可定义的比较，既能得到可重复核对的结果，也能把“不包含实际写入权限”写进接口。

类比装修顾问懂沟通，但测量尺寸用尺子、供电操作找有资质的执行人员。类比边界：程序工具不天然有资质或正确，权限和实现都需验证；不能因为叫工具就完全信任。

小问题：工具返回版本不一致，模型觉得“差一版没关系”，能覆盖工具结果吗？不能把自己的判断冒充确定性比较；业务例外必须有明确规则和授权。

## 2. 工具把什么交给程序？

**工具（tool）**是一个输入、操作、输出有约定的能力。它可以是纯计算、只读资料查询，也可以是有副作用的业务动作。**副作用**指改变外部状态，例如发消息、改订单、扣款。今天只提供纯比较，没有副作用。

**契约（contract）**就是双方预先约定“接收什么、拒绝什么、返回什么”。不是法律文件，而是可检查的接口规则。

| 要素 | 本课工具契约 |
| --- | --- |
| 名字 | compare_revision |
| 输入 | base和current，均正整数 |
| 动作 | 比较是否相等 |
| 输出 | matches与write_authorized=false |
| 明确不做 | 查真实工单、变更记录、审批或派单 |

名字相同但规则不同，结果不可直接比较；工具版本和业务口径变更也应管理。这与聊天提示“请仔细比较”不同，程序会对不合法输入返回错误。

## 3. 为什么输入校验比“模型很聪明”更可靠？

先看三个输入：

```text
base=4, current=5        合法，比较结果False
base="4", current=5      非法，字符串不是本课要求的整数
base=True, current=5     非法，布尔值不是业务版本号
```

双引号表示文字“4”；没有引号的4是整数。**类型**是程序怎样解释这个值的类别。允许自动把字符串转整数可以是另一种契约，但必须明确；本课严格拒绝，避免静默猜测。

Python中bool与int有继承关系，所以代码用`type(value) is int`表达“只接受整数，不收True/False”。初学不必记继承细节，只要知道校验规则要符合业务，而不是看值“好像差不多”。

小问题：多传一个force=true字段，是为了方便，能收下吗？不能。本课不允许额外字段，尤其不能让未知参数变成绕过检查的开关。

## 4. 模型与工具怎样形成受控循环？

延续第八期，把职责再具体化：

```text
模型提出compare_revision(base=4,current=5)
→ 应用检查工具和参数
→ 工具返回matches=false
→ 应用把这个观察交回模型
→ 模型解释“提案版本与快照不一致，请重读重审”
```

模型生成动作意图，程序执行契约，结果回到模型输入。这会改变下一次生成的条件，而不是把工具结果训练进参数。

若工具报“正整数必需”，模型可以在剩余预算内修正；不能为了得到答案关闭校验。若仍无法提供合法输入，就结束并说明缺项。今日Agent使用最多4轮、每轮3工具，是显式预算，不允许无限循环。

**审计轨迹**可以记录工具名字、合法输入、结果/错误、时间与来源；不必记录或公开模型内部思维。真实运行还要脱敏并控制日志访问，本课不产生运行日志文件。

## 5. 原理：输出可靠性是几条链相乘的直觉

为帮助理解，可把成功条件写成逻辑连接，而不是虚构概率：

```text
输入合法 且 对象正确 且 工具实现符合规则
且 证据适用 且 模型正确使用结果 且 行动有授权
```

**且**表示每项都要满足；其中一项失败，不能声称完整业务成功。这里没有假设各项独立，也没有编造“工具提升准确率多少”的数字。

例如4与5比较正确，但这两个版号来自错工单，业务结论仍错；版号来自正确工单但采集过期，也不能保证提交时版本；模型正确说“不一致”，但程序仍开放无条件写工具，安全问题依然存在。

可口述的最小链是“输入→校验→执行→结果→解释→授权”。把它拆开之后，出错能定位到具体环节，而不只是怪模型。

## 6. 最小离线例子：四个调用意图

前提：Python 3.11+、无额外包或GPU。Windows打开PowerShell，进入仓库根目录：

```powershell
python --version
python llm-zero-to-one/examples/day009_tool_contract_lab.py
```

完整文件：[day009_tool_contract_lab.py](../examples/day009_tool_contract_lab.py)。四个调用是我们手写的，**不是模型生成**；程序不接真实工单、不联网、不写文件，不是完整Agent。按源码推导的预期，尚未执行：

```text
{'matches': False, 'write_authorized': False}
{'error': 'Positive integer revisions required'}
{'matches': True, 'write_authorized': False}
{'error': 'tool_not_allowed'}
```

第一条合法不匹配；第二条把4写成字符串而被拒；第三条匹配也不授权写入；第四条要求update_record，工具没有被注册，直接拒绝。

若终端找不到python先查解释器路径；若找不到文件检查目录；显示error不一定是程序故障，第二和第四条正是在验收拒绝路径。

## 7. 分段讲清程序在做什么

以下来自完整文件，不能独立运行：

```python
if not isinstance(arguments, dict) or set(arguments) != {"base", "current"}:
    raise ValueError("Exactly base and current required")
```

`dict`是按名字保存值的字典。先要求传入字典，再比较键的集合必须刚好两个；少字段、多字段都拒绝。`raise ValueError`表示把不合法输入明确反馈出来。

```python
if call["name"] != "compare_revision":
    return {"error": "tool_not_allowed"}
```

这段属于**分发器**：按名字找到允许的能力。没有使用eval执行模型输出，也不按模型传入字符串动态导入任意函数。模型想调用写工具，不代表应用要提供。

```python
return {"matches": arguments["base"] == arguments["current"], "write_authorized": False}
```

`==`比较两个数值是否相同，不改变记录。输出特意把匹配与写入授权分开。真实服务还需把结构化输出交给后续逻辑，不只让人看一段漂亮总结。

## 8. 工具也会错，应该怎么验收？

对本课，最小验收包括合法匹配、合法不匹配、字符串/布尔等错误类型、多字段、未允许的工具。对真实查询工具，还要测错对象、陈旧来源、超时、空结果和权限范围；对写工具，还要测幂等、版本竞争、重复回调和恢复。

工具返回成功不代表整个Agent成功；模型可能曲解、漏报错误或过度承诺。至少对照结构化报告与最终文字，标识哪些是工具事实、哪些是建议、哪些需要人工补证。

本课只准备了离线示意与逻辑检查，没有跑模型准确率评测。今日[工单修订Agent](../../examples/revision-conflict-review/README.md)进一步把提案、快照和审查工具组成循环，但仍只读，不实现真正的CAS写入。

## 9. 工具越多越好吗？

不是。工具太多增加描述长度、选择歧义和权限面。建议从一个业务问题最必要的几项能力开始，输入保持小而明确，输出带来源与错误。

纯比较不需要网络；结构化配置不一定需要RAG；复杂状态恢复适合LangGraph；业务触发可以用n8n；可视化知识运营再考虑Dify；LangChain在适配有实际价值时引入。框架名字不是验收证据。

先决定业务需要哪个操作，再决定由谁编排、如何验证；不要为了使用四个框架，把一个简单工具调用拆成多个相互重试的系统。

## 10. 常见误区与定位

| 误区/现象 | 该核对什么 |
| --- | --- |
| 工具结果正确但答案反了 | 模型是否正确引用matches及对象 |
| 同样输入结果变化 | 是否真正纯函数、是否外部状态/时间变化 |
| 错误后一直循环 | 是否有轮数、工具数和总时间上限 |
| 工具名看起来合法就执行 | 分发白名单和参数校验是否在程序里 |
| matches=true就改记录 | 授权与原子提交条件是否独立 |
| 引用source所以可信 | 证据身份、时间及支持关系是否通过 |

## 11. 练习与解释性答案

1. base=5,current=5，能不能修改工单？**本工具不能。**它只做比较，write_authorized始终false。
2. base=True,current=1，是业务上的匹配吗？**先拒绝。**本契约不接受布尔值为版本号，不能只依赖语言默认相等行为。
3. 模型输出update_record，是否要新增函数帮它完成？**不应自动新增。**执行范围来自业务授权，不来自模型请求。
4. 工具查到正确版号，但模型说“已经写入”，怎么办？**视为错误宣称。**核对轨迹，不能把模型自述当执行证据。
5. 今日例子是否需要向量数据库？**不需要。**正整数相等比较没有语义检索需求。
