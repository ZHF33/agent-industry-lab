# Day 001｜大模型到底是什么？从“会接话”到“能交付”

[课程首页](../README.md) · [完整计划](../PLAN-365.md) · [资料来源](../SOURCES.md)

**今天只解决一个问题：模型、资料、工具、应用分别做什么？** 不需要代码基础、不需要安装软件、不需要GPU。学完交一张应用图和一张任务卡，不用背模型排行榜。

## 1. 从一个面包店问题开始

老板说：“帮我写一条新品面包介绍，再算一下12个面包每个8.5元多少钱。”你把要求发给一个聊天助手，它很快写出漂亮文案，还可能说“新品低糖、每天现烤、今天有优惠”。

这里至少有三个不同任务：写文案、知道商品事实、计算金额。语言流畅不保证商品信息真实，也不保证金额正确。如果资料里没有低糖、优惠和现烤承诺，这些话就不能当店铺事实发布。

我们希望系统做到：从批准资料取商品事实，让模型组织语言，让程序计算12×8.5，再交人检查。第一天先建立这个分工，后面学的RAG、Agent和工作流都有位置，不会只剩堆名词。

小问题：回答很像专业文案，是否说明它查过商品档案？**不是。** 必须看应用是否真的提供或查询了资料，以及结论有没有证据支持。

## 2. 大语言模型是什么？先不谈公式

**模型**是通过数据训练得到的一套计算规则和数字参数。**语言模型**学习语言片段在上下文中如何关联；许多生成式大语言模型会根据已有内容预测后续片段，再逐步生成文本。LLM是Large Language Model的缩写，中文常说“大语言模型”。

可以把它先想成见过大量语言例子、很擅长组织和续写表达的助手。但这个类比只帮助理解输出过程：它没有人的生活经历或业务职责，也不是一个完整保存原始文章、随问随查的文件柜。

“大”没有一个适用于所有场景的统一参数门槛；模型能力还受数据、训练方式、结构、使用条件等影响。今天不靠参数多少决定能否做你的业务。

**参数**可以类比训练时调出来的许多旋钮。训练调整旋钮；正常使用时则用已有旋钮处理输入。参数不等于一张张可以按文件名检索的资料卡。这个类比也有限：实际参数是数字张量，并非每个旋钮单独代表一个明确事实。

小问题：我在聊天里贴了一段店铺资料，是否已经把模型重新训练了？**通常没有。** 这段资料被用作本次或后续对话的上下文；产品可能另外保存记录，但“保存对话”“检索记忆”和“更新模型参数”是不同事情。

## 3. 为什么它会说得很顺，却可能说错？

预测合适的语言表达，与核实每个现实事实是两个目标。缺少依据时，模型仍可能补出看起来合理的名字、数字或条件。人们常把这类没有依据却像真的生成内容叫**幻觉**。

例如只给“新品面包”，模型也许补出“无糖”。即使某些面包确实无糖，也不证明这一个产品无糖。错误未必是故意欺骗，工程上仍要防止它影响业务。

“请保证真实”是一条要求，不是一种查证工具。正确做法是明确事实来源、约束缺失信息的处理，并让程序和人核对。不能把一句免责声明当作整个系统设计。

## 4. 三个基本词，先够用

**Token（词元或语言片段）**：模型处理文本时使用的单位，可能是一个字、词的一部分、标点或其他片段；具体划分由分词器决定。不能简单说一个中文字符永远等于一个Token。

**Prompt（提示输入）**：交给模型的任务说明、资料及相关上下文。不是一句神奇口令，清楚的任务、边界和资料通常比堆“你是顶级专家”更便于检查。

**Context（上下文）**：模型当前能用到的信息。像一张有限大小的工作台，可以摆任务、对话和文档片段。桌上有一本资料不等于模型一定正确使用，也不等于这本书永远保存在模型参数里。

小问题：上下文装得下更多资料，是否一定更准确？**不一定。** 资料可能冲突、过期或不相关，系统还需要选择证据和验证回答。

## 5. 模型、应用、资料与工具四层图

```text
用户的任务
    ↓
应用：接收输入、检查格式、组织步骤、显示结果
    ├─ 资料：批准的商品说明、订单或手册
    ├─ 模型：理解任务、组织语言、按约定选择工具
    └─ 工具：查询、精确计算等可执行函数
    ↓
结果与来源 → 人工审核 → 另行授权的业务动作
```

**应用**是把这些能力组织起来的程序或产品。聊天页面只是可能的界面，不等于模型本身。一个模型可以服务多个应用，一个应用也可能调用多个模型或根本不需要模型。

**工具**是程序实际执行的函数，例如计算总价。模型写“我查到了订单”不代表程序真的查询；必须有工具执行及返回结果。工具能做什么取决于程序提供的能力和权限，不能因为模型想执行就放行。

**RAG（检索增强生成）**的基本思路是先找相关资料，再把证据交给模型生成回答。今天只认识位置，后面再讲怎样找、引用和评估；普通复制粘贴一段资料不等于已经建好了完整RAG系统。

**Agent（智能体）**在本课程里指能在受控循环中选择下一步或工具、执行后读取结果再继续的系统。它需要停止条件、权限和错误处理。固定按顺序跑几个步骤的工作流可以很有用，但不能仅凭流程图就声称模型在自主决策。

第一期不用安装LangChain、LangGraph、Dify或n8n。等业务流程有需要再引入，并明确谁负责哪一步。

## 6. 无软件练习：给请求分工

先看合成资料卡：

```text
产品：演示原味面包
售价：每个8.50元
配料：面粉、水、酵母、盐
过敏原：含小麦
未提供：含糖量检测、健康功效、当天优惠
```

任务A：“写40字以内介绍。”交给模型组织表达，但事实只能来自资料。可接受的示意回答：“演示原味面包，每个8.50元，配料含面粉、水、酵母和盐；含小麦。”这只是人为编写的教学示例，不是实际模型输出。

任务B：“12个多少钱？”让计算工具算102.00元。模型可以解释结果，不必让它重新心算。

任务C：“适合糖尿病患者吗？”资料不足，也涉及个体健康问题，系统不能从配料表推断适用结论；应说明缺少依据，不能制作健康适用承诺。

任务D：“把介绍发到真实店铺账号。”这是对外业务动作，需要明确授权、内容审核及账号权限。本例只写草稿，不执行发布。

小问题：任务C资料不足，回答“不知道”算失败吗？**不是。** 在没有依据时停止推断，是正确边界，比编一个肯定答案更符合要求。

## 7. 可选最小代码：用确定计算核对金额

不想运行可先手工推演。愿意看代码时，配套[day001_task_card.py](../examples/day001_task_card.py)只用Python标准库，不调用模型、不访问网络、不读真实数据。

前提：电脑已有Python3.12或更新版本。打开PowerShell，进入仓库目录；“进入目录”表示告诉终端从哪个文件夹找文件：

```powershell
cd H:\CodeX\Carreer\agent-industry-lab\runtime\publish-20261014
python llm-zero-to-one/examples/day001_task_card.py
```

其他读者把cd后路径换成自己下载仓库的目录。如果提示python不是命令，说明环境前提没满足，今天先做纸笔任务，不需要为这一课安装模型或购买服务。

核心代码逐行看：

```python
unit_price = Decimal("8.50")
quantity = 12
total = unit_price * quantity
```

Decimal是Python提供的十进制数工具，适合这里精确表示金额。引号里的8.50是文字，转换后才作为十进制数计算；quantity是数量；最后一行得到总价。这里没有神经网络，也没有Agent，这正是目的：该用简单计算解决的事情，不必让模型猜。

预期输出如下；本次只审查代码语法与逻辑，不把预期称为实际运行结果：

```text
任务：生成商品介绍草稿
已知：产品、价格、配料、过敏原
缺失：含糖量检测、健康适用结论
12个合计：102.00元
发布权限：需人工另行授权
```

如果出现SyntaxError，表示代码格式有问题；文件找不到先检查当前目录；如果有人把代码换成API调用后出现网络错误，那已经超出本例，不能拿这个结果声称第一期“模型验证通过”。

## 8. 今天交一张任务卡

不必写代码，用自己的话填下面七行：

1. 用户：谁需要这个结果？
2. 任务：只做一件什么事？
3. 输入：已有哪些事实，来源在哪里？
4. 模型：需要理解或生成什么？
5. 工具：查询或计算由谁执行？
6. 输出：需要哪些字段，怎么知道满足要求？
7. 人工：哪些决定和动作仍需确认？

示例答案：面包店店员需要商品介绍草稿；输入为批准资料卡；模型改写介绍；程序计算总价；输出介绍、金额、来源与缺项；人工核对商品事实，对外发布另行授权。

验收不是“写满七行”就通过：请找一条资料中没有的承诺，确认任务卡不会把它变成事实；再把数量换成0或负数，指出后续程序应拒绝非法数量。本例固定12，不声称已实现通用输入校验。

## 9. 五题自测与解释性答案

一：模型是否天然连接公司资料？**否。** 需要应用传入资料或受控查询工具。

二：输入一段对话是否等于重新训练？**通常否。** 使用上下文不等于改变参数；产品保存行为另看其机制。

三：输出很流畅是否代表事实正确？**否。** 需要证据和检查。

四：给模型加计算工具是否所有金额都可靠？**否。** 工具输入、数量、单位和公式也可能错误。

五：写成草稿后是否可以自动发给客户？**否。** 外部动作要有明确权限与审核，本课没有执行工具。

## 10. 常见误区与下一期准备

误区是“先装一堆框架才能开始”。今天的任务卡和分工图已经是有效工程准备。另一个误区是“模型不能保证事实，所以没有价值”：合理分工后，模型仍可帮助理解需求、组织语言和提出候选步骤，事实与动作则有明确约束。

下一期区分“模型”和“聊天产品”。带上今天的四层图，尝试指出聊天界面、文档检索、计算器分别属于哪一层。今天只需掌握分工，不要求解释注意力公式或训练损失。
