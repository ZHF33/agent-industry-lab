## 1. 从一个面包店问题开始

老板说：“帮我写一条新品面包介绍，再算一下12个面包每个8.5元多少钱。”你把要求发给一个聊天助手，它很快写出漂亮文案，还可能说“新品低糖、每天现烤、今天有优惠”。

这里至少有三个不同任务：写文案、知道商品事实、计算金额。语言流畅不保证商品信息真实，也不保证金额正确。如果资料里没有低糖、优惠和现烤承诺，这些话就不能当店铺事实发布。

我们希望系统做到：从批准资料取商品事实，让模型组织语言，让程序计算12×8.5，再交人检查。第一天先建立这个分工，后面学的RAG、Agent和工作流都有位置，不会只剩堆名词。

小问题：回答很像专业文案，是否说明它查过商品档案？**不是。** 必须看应用是否真的提供或查询了资料，以及结论有没有证据支持。

## 2. 大语言模型是什么？先不谈公式

**模型**是通过数据训练得到的一套计算规则和数字参数。**语言模型**学习语言片段在上下文中如何关联；许多生成式大语言模型会根据已有内容预测后续片段，再逐步生成文本。LLM是Large Language Model的缩写，中文常说“大语言模型”。

可以把它先想成见过大量语言例子、很擅长组织和续写表达的助手。但这个类比只帮助理解输出过程：它没有人的生活经历或业务职责，也不是一个完整保存原始文章、随问随查的文件柜。

“大”没有一个适用于所有场景的统一参数门槛；模型能力还受数据、训练方式、结构、使用条件等影响。今天不靠参数多少决定能否做你的业务。

**参数**可以类比训练时调出来的许多旋钮。训练调整旋钮；正常使用时则用已有旋钮处理输入。参数不等于一张张可以按文件名检索的资料卡。这个类比也有限：实际参数是数字张量，并非每个旋钮单独代表一个明确事实。

小问题：我在聊天里贴了一段店铺资料，是否已经把模型重新训练了？**通常没有。** 这段资料被用作本次或后续对话的上下文；产品可能另外保存记录，但“保存对话”“检索记忆”和“更新模型参数”是不同事情。

## 3. 为什么它会说得很顺，却可能说错？

预测合适的语言表达，与核实每个现实事实是两个目标。缺少依据时，模型仍可能补出看起来合理的名字、数字或条件。人们常把这类没有依据却像真的生成内容叫**幻觉**。

例如只给“新品面包”，模型也许补出“无糖”。即使某些面包确实无糖，也不证明这一个产品无糖。错误未必是故意欺骗，工程上仍要防止它影响业务。

“请保证真实”是一条要求，不是一种查证工具。正确做法是明确事实来源、约束缺失信息的处理，并让程序和人核对。不能把一句免责声明当作整个系统设计。

## 4. 三个基本词，先够用

**Token（词元或语言片段）**：模型处理文本时使用的单位，可能是一个字、词的一部分、标点或其他片段；具体划分由分词器决定。不能简单说一个中文字符永远等于一个Token。

**Prompt（提示输入）**：交给模型的任务说明、资料及相关上下文。不是一句神奇口令，清楚的任务、边界和资料通常比堆“你是顶级专家”更便于检查。

**Context（上下文）**：模型当前能用到的信息。像一张有限大小的工作台，可以摆任务、对话和文档片段。桌上有一本资料不等于模型一定正确使用，也不等于这本书永远保存在模型参数里。

小问题：上下文装得下更多资料，是否一定更准确？**不一定。** 资料可能冲突、过期或不相关，系统还需要选择证据和验证回答。

## 原理加深：一句话究竟怎样变成回答？

下面以常见的**自回归文本生成模型**为对象。“自回归”先理解成：每生成一小段，就把这一段接到已有内容后面，再继续。不是所有模型都按同一种结构工作；本节是一条具体学习主线，不是对全部AI的定义。

这一部分对应[LLM Course的架构主题](https://github.com/mlabonne/llm-course#1-the-llm-architecture)，并用[Transformer原论文第3节](https://arxiv.org/html/1706.03762v7)核查结构。以下数字、句子、练习都是原创教学示意，不是某个真实模型的测量结果。

### A. 为什么不能直接把中文交给计算器？

先想商店商品：电脑不能因为看见“原味面包”四个字，就自然知道它的售价。程序需要一种明确的表示，例如商品编号与价格表。语言模型同样要把输入转换成可以计算的数据。

通常先有**分词器（tokenizer）**，把文字拆成词元，再把每个词元映射为词表中的整数编号。词表可以理解为“系统允许使用的片段与编号对照表”。例如我们人为约定：

| 片段 | 教学编号 |
| --- | ---: |
| 面包 | 17 |
| 每个 | 28 |
| 8.50 | 43 |
| 元 | 64 |

那么“面包每个8.50元”可以在这个玩具约定下表示为`[17, 28, 43, 64]`。**这不是任何真实分词器的结果**。现实中的数字、小数点、汉字可能按不同方式拆开，取决于分词器的规则和词表。

这里有两个动作，不能混在一起：先决定“怎么切”，再决定“每块用什么编号”。[Hugging Face的BPE教材](https://huggingface.co/learn/llm-course/chapter6/5?fw=pt)展示了其中一种分词方法；不是所有分词器都完全相同。

小问题：编号64比17大，是不是表示“元”比“面包”更重要？**不是。** 编号首先是查找身份；像学号大的学生并不天然更优秀。也不能直接拿编号差值衡量语义距离。

### B. 编号怎样变成有用的数字表示？

下一步是**嵌入（embedding）**：按编号找到一串数字。这串数字叫**向量**，先把向量理解成按顺序排好的一组数字。

例如，给“面包”设一个教学向量`[0.2, -0.1, 0.7]`。三项一起才构成它的表示。真实模型的维度由结构确定；这些数一般在训练中学到，不是人给每个词手填“食物程度”“贵的程度”。同一个维度也通常不能直接翻译成一个清楚的中文属性。

为什么不用一个编号算到底？因为一个整数主要区分身份，一组可学习的数字则能经过矩阵运算组合与变换，承载对任务有用的关系。后面学检索时还会遇到“整段文字的向量”：它和生成模型内部某个词元的表示不能不加区分地混用。

还需要表达顺序：“店员问顾客”和“顾客问店员”使用相似词语，含义却不同。模型要引入**位置信息**。具体方法有多种，今天只需知道，文字内容与前后顺序都要进入计算。

小问题：把一句话的词序打乱，只要词元一样，模型接收到的信息是否就一样？**不是。** 顺序变化会影响位置与上下文计算。

### C. 注意力为什么有用？它不是人在集中精神

看合成句子：“顾客把面包递给店员，因为店员要检查包装。”要理解后半句里的动作，不能只看眼前一个词，需要结合前面的相关位置。

**注意力（attention）**是一种计算机制：当前位置用自己的表示，对允许读取的位置计算匹配分数，再按权重汇总那些位置的信息。“注意”是名字，不表示计算机产生了人的主观注意或意识。

可以类比开会：你带着一个问题，比较其他人的发言与当前问题的关联程度，再把有关信息汇总。但模型不会真的开会；比较与汇总实际由数字运算完成，而且不保证“分数高”就一定符合人类理解。

稍深一层，后面会用三个字母：

- **Q（query，查询表示）**：当前位置用什么线索找信息。
- **K（key，键表示）**：其他位置提供什么线索供匹配。
- **V（value，值表示）**：匹配后要汇总的内容。

这里“查询”指模型内部计算，不代表自动联网或检索数据库。Q、K、V通常由已有表示经过可学习的变换得到。今天不要求计算矩阵乘法，先把“匹配用的线索”和“汇总的内容”区分开。

用一个完全人为的单头示例看加权汇总：

| 允许读取的位置 | 归一化权重 | 简化为一个数的V |
| --- | ---: | ---: |
| 位置A | 0.7 | 10 |
| 位置B | 0.2 | 20 |
| 位置C | 0.1 | 30 |

结果为`0.7×10 + 0.2×20 + 0.1×30 = 14`。这里展示的是“按权重混合信息”。真实V是向量，不是单个价格；权重也不是我们手填的业务置信度。注意力权重更不能直接当成对模型全部决策的完整解释。

**因果遮罩**可以理解为挡住答案的一张纸：预测某个训练位置的后续片段时，不能直接读取后面的正确答案。否则训练时像在抄答案，实际生成时却没有那份答案可抄。常见因果注意力允许当前位置读取当前及更早的位置，禁止读取未来位置。

注意力也不是整个模型：还会有逐位置的信息变换、残差连接和归一化等结构。**残差连接**先理解为保留一条原信息通路；**归一化**先理解为按规则调整数值尺度。它们的计算细节留到机制模块；今天只需避免“模型内部只有一张注意力表”的误解。

小问题：模型会注意前面的“价格8.50元”，是否证明它一定引用正确？**不证明。** 信息有机会进入计算，与最后回答正确是不同层次。

### D. 从数字分数到下一个片段

经过多层计算后，模型会为词表中的候选词元产生分数，常称为**logit（未归一化分数）**。这些数还不是概率，可以为负，也不必加起来等于1。

模型或生成程序把分数转换成概率分布，再按某种规则选择下一词元。概率分布先理解成一张“下一步各候选的份额表”，所有份额合计100%。

下面只演示三个候选；现实模型面对的是整个词表或经过筛选后的候选集合。我们选特别好算的人工分数：

| 候选 | 人工分数 | 转换后概率 |
| --- | ---: | ---: |
| A | ln(6) | 60% |
| B | ln(3) | 30% |
| C | ln(1) | 10% |

不会对数也能理解这一步：这里特意让“指数变换”之后的正数是6、3、1，再除以合计10，就得到0.6、0.3、0.1。**softmax**就是这种把一组分数变成概率份额的常用变换。ln叫自然对数，在这里仅用于构造容易核对的例子。

给愿意看公式的读者：

`p_i = exp(z_i / T) / Σ_j exp(z_j / T)`

逐个读：`z_i`是第i个候选的分数；`exp`把数字变成正数；`Σ_j`表示把所有候选的对应数加起来；分母使份额总和为1；`T`叫温度，本式先要求它大于0。今天不必会求导。

选择时有两种不同思路：

- **贪心选择**：直接取概率最大的候选。例中总选A。
- **采样**：按份额随机抽取。一次可能选A，也可能选B或C；60%不表示每10次必有6次A。

**温度（temperature）**改变份额的集中程度。在同样的人工分数下，T从1降到0.5，变换后的相对数是36、9、1，对应约78.26%、19.57%、2.17%。最大候选更集中，但没有凭空多出商品资料。这里假设候选和其他解码设置不变。

T=0不能直接代进上面的除法；有些接口用它表示接近贪心的特殊设置。具体语义、范围和支持情况要查对应服务。固定温度也不等于任何环境下都完全复现。

关键问题：A的生成概率60%，是不是“它说的事实有60%概率正确”？**不是。** 它是当前输入条件下下一词元的生成概率，不是已经校准过的事实正确率。最大概率的后续片段也可能构成一个错误答案。降低温度无法单独解决这个问题。

### E. 一次选完，为什么能写出整段话？

先给模型一段输入，算下一词元；选出一个词元并接回去，再算下一词元。这个“使用自己刚输出的内容继续生成”的过程，就是本节所说的自回归生成。

```text
任务与资料 → 分词和编号 → 数字表示与位置信息
          → 多层上下文计算 → 下一词元分数 → 选择词元
                                   ↑              │
                                   └─ 接回已有序列 ┘
```

实际系统还会设置停止标记、最大输出长度、超时或取消。到达长度上限不意味着业务问题已经解决；它只表示本次生成被截断或结束。

生成步骤在本例中依次展开，但训练时可以利用已知文本和遮罩，在一次计算中处理许多位置的预测。不要从“逐步生成”误推出“训练永远只能每次算一个词”。一些推理优化也会采用更复杂的生成策略，后续再展开。

### F. 模型怎样学会这些计算？

可以先用“做题—看差距—调方法”理解训练，但不能把它当成人的读书过程。训练系统拿一段文本，构造许多预测任务，例如给出前面的内容，要求提高真实后续词元的预测概率。它从文本本身形成目标，所以常叫**自监督学习**：目标不一定需要人逐条额外标注。

**损失（loss）**是用来衡量预测与训练目标差距的数。对一个正确目标，最简单的单位置交叉熵写成：

`L = -ln(p_目标)`

如果正确后续片段只得到0.1概率，损失约2.303；得到0.6概率，损失约0.511。它表达的是：给实际目标更低概率，会受到更大惩罚。完整训练通常汇总很多位置与样本的损失，具体还可能有其他目标。

接下来通过**梯度**计算参数改变时损失如何变化，再由**优化器**按规则更新参数。梯度可以先类比坡度，帮助决定往哪个方向调；真实模型有大量相互影响的参数，并不是找到一个独立“面包事实旋钮”改一下。

训练不保证记住每条事实，也不保证在新问题上正确。模型可能学到可迁移规律，也可能记住局部样本，甚至继承数据中的错误。**泛化**指能否把学到的能力用于没见过的样本，不能只看训练题做得好不好。

### G. 预训练、微调、上下文与RAG，究竟改了哪里？

| 方法 | 核心动作 | 通常改变模型参数吗？ | 面包店例子 |
| --- | --- | --- | --- |
| 预训练 | 用大量数据学习通用预测规律 | 是 | 获得语言表达等基础能力；不等于知道这家店今天的价格 |
| 监督微调 | 用任务输入与合适输出继续训练 | 是，可能只更新适配参数 | 学习按“介绍、过敏原、缺失项”的业务格式回答 |
| 上下文示例 | 本次输入里提供少量完成范例 | 通常否 | 示范缺少营养资料时如何写“未提供” |
| RAG | 从外部资料检索片段再放入输入 | 普通检索与回答阶段通常否 | 查到今天批准的价格和产品说明 |

**少样本提示（few-shot prompting）**是输入少量范例来影响当前任务的生成方式；不是看到几个例子就自动做一次梯度更新。这一点可对照[GPT-3论文](https://arxiv.org/abs/2005.14165)。

RAG中的检索器或嵌入模型也可能单独训练，但“可能训练检索器”与“每次查资料都重新训练生成模型”不是一回事。[Universe的RAG章节](https://github.com/datawhalechina/llm-universe/blob/main/docs/C1/C1.md#12-什么是-rag)可作为应用方向的继续阅读。

小问题：店里价格从8.50变成9.00元，先考虑什么？**先更新权威业务资料及相关索引、缓存，再检查回答是否使用新版本。** 频繁变动的事实通常不适合只依靠重新训练来维护。

### H. 由机制解释：为什么会“说得像真的”？

生成目标与现实查证并不相同。模型从训练数据和输入形成一个后续分布，却不天然拥有店铺数据库的当前状态。信息缺失、资料错误、旧知识、误解上下文或后续计算失误，都可能造成错误。

因此模型“经常见过低糖面包的介绍”，并不能支持“这款面包低糖”。概率计算再精细，也不能把缺少的检测报告变出来。微调和事实检索各有帮助，但都不是消除全部错误的证明。

提示为何有用？因为任务、资料与范例改变了模型当前用来生成的条件。这能帮助限定所需行为；但提示本身不是程序执行权限。把资料用标签括起来有助于识别边界，却不能独立防止提示注入。[Cookbook的提示原则](https://github.com/datawhalechina/llm-cookbook/blob/main/docs/C1/2.%20提示原则%20Guidelines.md)可用来练习清晰表达，本课程同时保留程序校验与权限控制。

### I. 一次不用安装模型的原理实验

本实验是纸笔推演，不是模型推理记录。给三个候选A、B、C使用上面的人工分数。

1. T=1时把6、3、1加起来，用每项除以10，写下三项概率。
2. T=0.5时用36、9、1除以46，保留两位百分数。
3. 假设正确目标是C，观察温度降低后它的份额怎样变化。
4. 把“选中次数多”和“事实正确”分开写一句解释。

**解释性答案**：第一组为60%、30%、10%；第二组约78.26%、19.57%、2.17%。如果正确目标恰是C，温度降低反而让C更难被采到。这个人工反例足以说明“低温度保证正确”在逻辑上不成立，但不能用它估计真实模型的错误率。

再手算注意力例子：把位置C的V从30改成50，暂时保持权重不变，汇总值从14变成16。它说明结果既依赖权重，也依赖被汇总的信息。真实模型中改输入可能同时改变权重，所以这只是控制单一变量的数学演示。

最后画训练与生成两条线：训练线必须出现“目标、损失、参数更新”；普通生成线必须出现“使用已有参数、选择下一词元、停止”。如果两条线都画成“读一句话就改参数”，还需要回看F、G两节。

### J. 自测：能解释因果，才算懂了一层

1. **模型的词元编号为什么不能直接当语义坐标？** 编号用来标身份，大小与距离没有天然语义；嵌入才提供可学习的数字表示。
2. **注意力的“查询”是不是联网搜索？** 不是，本节是模型内部表示之间的匹配。联网需要额外工具与应用执行。
3. **因果遮罩为何必要？** 防止训练时预测位置读取未来目标，保持任务与生成时的信息条件相符。
4. **把正确目标概率从0.1提高到0.6，损失怎样变？** 从约2.303降到0.511；这是目标预测改善，不能直接等同全部业务质量提升。
5. **低温度为什么可能稳定地答错？** 它让已有高概率候选更集中；若高概率候选错误，集中不提供事实纠正。
6. **把价格贴进对话，和为价格做微调差在哪里？** 前者改变当前输入，后者涉及训练与参数更新；两者还都要检查资料是否权威和最新。

本节不要求第一天掌握矩阵求导。合格标准是能用自己的话走通“文字变数字—结合上下文—算下一步—继续生成”，并能举一个概率高却错误的例子。公式与架构在后续单元逐层拆开，不能只在本课出现一次就算教完。


## 5. 模型、应用、资料与工具四层图

```text
用户的任务
    ↓
应用：接收输入、检查格式、组织步骤、显示结果
    ├─ 资料：批准的商品说明、订单或手册
    ├─ 模型：理解任务、组织语言、按约定选择工具
    └─ 工具：查询、精确计算等可执行函数
    ↓
结果与来源 → 人工审核 → 另行授权的业务动作
```

**应用**是把这些能力组织起来的程序或产品。聊天页面只是可能的界面，不等于模型本身。一个模型可以服务多个应用，一个应用也可能调用多个模型或根本不需要模型。

**工具**是程序实际执行的函数，例如计算总价。模型写“我查到了订单”不代表程序真的查询；必须有工具执行及返回结果。工具能做什么取决于程序提供的能力和权限，不能因为模型想执行就放行。

**RAG（检索增强生成）**的基本思路是先找相关资料，再把证据交给模型生成回答。今天只认识位置，后面再讲怎样找、引用和评估；普通复制粘贴一段资料不等于已经建好了完整RAG系统。

**Agent（智能体）**在本课程里指能在受控循环中选择下一步或工具、执行后读取结果再继续的系统。它需要停止条件、权限和错误处理。固定按顺序跑几个步骤的工作流可以很有用，但不能仅凭流程图就声称模型在自主决策。

第一期不用安装LangChain、LangGraph、Dify或n8n。等业务流程有需要再引入，并明确谁负责哪一步。

## 6. 无软件练习：给请求分工

先看合成资料卡：

```text
产品：演示原味面包
售价：每个8.50元
配料：面粉、水、酵母、盐
过敏原：含小麦
未提供：含糖量检测、健康功效、当天优惠
```

任务A：“写40字以内介绍。”交给模型组织表达，但事实只能来自资料。可接受的示意回答：“演示原味面包，每个8.50元，配料含面粉、水、酵母和盐；含小麦。”这只是人为编写的教学示例，不是实际模型输出。

任务B：“12个多少钱？”让计算工具算102.00元。模型可以解释结果，不必让它重新心算。

任务C：“适合糖尿病患者吗？”资料不足，也涉及个体健康问题，系统不能从配料表推断适用结论；应说明缺少依据，不能制作健康适用承诺。

任务D：“把介绍发到真实店铺账号。”这是对外业务动作，需要明确授权、内容审核及账号权限。本例只写草稿，不执行发布。

小问题：任务C资料不足，回答“不知道”算失败吗？**不是。** 在没有依据时停止推断，是正确边界，比编一个肯定答案更符合要求。

## 7. 可选最小代码：用确定计算核对金额

不想运行可先手工推演。愿意看代码时，配套[day001_task_card.py](../examples/day001_task_card.py)只用Python标准库，不调用模型、不访问网络、不读真实数据。

前提：电脑已有Python3.12或更新版本。打开PowerShell，进入仓库目录；“进入目录”表示告诉终端从哪个文件夹找文件：

```powershell
cd H:\CodeX\Carreer\agent-industry-lab\runtime\publish-20261014
python llm-zero-to-one/examples/day001_task_card.py
```

其他读者把cd后路径换成自己下载仓库的目录。如果提示python不是命令，说明环境前提没满足，今天先做纸笔任务，不需要为这一课安装模型或购买服务。

核心代码逐行看：

```python
unit_price = Decimal("8.50")
quantity = 12
total = unit_price * quantity
```

Decimal是Python提供的十进制数工具，适合这里精确表示金额。引号里的8.50是文字，转换后才作为十进制数计算；quantity是数量；最后一行得到总价。这里没有神经网络，也没有Agent，这正是目的：该用简单计算解决的事情，不必让模型猜。

预期输出如下；本次只审查代码语法与逻辑，不把预期称为实际运行结果：

```text
任务：生成商品介绍草稿
已知：产品、价格、配料、过敏原
缺失：含糖量检测、健康适用结论
12个合计：102.00元
发布权限：需人工另行授权
```

如果出现SyntaxError，表示代码格式有问题；文件找不到先检查当前目录；如果有人把代码换成API调用后出现网络错误，那已经超出本例，不能拿这个结果声称第一期“模型验证通过”。

## 8. 今天交一张任务卡

不必写代码，用自己的话填下面七行：

1. 用户：谁需要这个结果？
2. 任务：只做一件什么事？
3. 输入：已有哪些事实，来源在哪里？
4. 模型：需要理解或生成什么？
5. 工具：查询或计算由谁执行？
6. 输出：需要哪些字段，怎么知道满足要求？
7. 人工：哪些决定和动作仍需确认？

示例答案：面包店店员需要商品介绍草稿；输入为批准资料卡；模型改写介绍；程序计算总价；输出介绍、金额、来源与缺项；人工核对商品事实，对外发布另行授权。

验收不是“写满七行”就通过：请找一条资料中没有的承诺，确认任务卡不会把它变成事实；再把数量换成0或负数，指出后续程序应拒绝非法数量。本例固定12，不声称已实现通用输入校验。

## 9. 五题自测与解释性答案

一：模型是否天然连接公司资料？**否。** 需要应用传入资料或受控查询工具。

二：输入一段对话是否等于重新训练？**通常否。** 使用上下文不等于改变参数；产品保存行为另看其机制。

三：输出很流畅是否代表事实正确？**否。** 需要证据和检查。

四：给模型加计算工具是否所有金额都可靠？**否。** 工具输入、数量、单位和公式也可能错误。

五：写成草稿后是否可以自动发给客户？**否。** 外部动作要有明确权限与审核，本课没有执行工具。

## 10. 常见误区与下一期准备

误区是“先装一堆框架才能开始”。今天的任务卡和分工图已经是有效工程准备。另一个误区是“模型不能保证事实，所以没有价值”：合理分工后，模型仍可帮助理解需求、组织语言和提出候选步骤，事实与动作则有明确约束。

下一期区分“模型”和“聊天产品”。带上今天的四层图，尝试指出聊天界面、文档检索、计算器分别属于哪一层。今天先口述生成链并手算人工概率与损失；注意力矩阵和梯度的完整计算留待机制模块。
