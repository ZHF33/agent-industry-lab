# Day018 命令行与工作目录

学完这期，你能读懂一条运行命令，知道程序从哪个位置找文件，区分终端提示符和真正输入的字符。前置是第16期路径和第17期文本编码，不需要模型、GPU或网络服务。

## 先把终端当作接待窗口
你向图书馆说“到二楼找 A 书架”，接待员先听指令，再按当前所在楼层理解相对位置。命令行是用文字输入指令的界面，PowerShell 是理解这些指令的程序，工作目录是这次操作的默认位置。

类比边界是计算机不按人的意图猜书架。文件名、引号和起点要符合规则。聊天里要求模型“打开文件”只生成文字时，不会自动改变终端目录。真正的访问来自应用授权执行的工具。

小练习是换了聊天窗口是否也换工作目录。答案是两者没有这种必然关系。要用命令实际查看。

## 一条命令怎样走到程序
看这条命令，以下是示意，暂时不用输入。

```powershell
python llm-zero-to-one/examples/day018_working_directory_lab.py demo-input.txt
```

PowerShell 先把这一行解析为程序名和参数。python 是解释器，解释器是读取并执行 Python 指令的程序。第一个参数是脚本文件，第二个是传给脚本的文本。程序名如何找到受安装和 PATH 环境配置影响，不能保证每台电脑都有同名命令。

解释器从当前目录定位相对脚本路径，然后读取脚本。脚本运行时继承启动进程的工作目录，并不会因为文件放在 examples 中就自动切到那里。后面的 demo-input.txt 作为字符串进入 sys.argv；只有脚本明确读取它时才会产生读取动作。

输入 → PowerShell解析 → 定位解释器 → 定位脚本 → 把参数交给脚本 → 脚本执行。这条机制是调试模型项目启动失败的前置链。

## 当前目录如何参与计算
记 C 为当前工作目录，p 为相对路径。常见文件路径在解释时从 C 组合得到位置，再由操作系统处理 . 和 .. 等部分。绝对路径有自己的起点，不能简单拼在 C 后面。

假设 C 为 H:/lab，脚本位于 H:/lab/examples/probe.py，传入 data.txt，那么读取相对 data.txt 通常定位 H:/lab/data.txt。从 H:/lab/examples 启动则定位 H:/lab/examples/data.txt。脚本未变，变的是启动位置。这与第16期的纸上路径相比，新增了终端和子进程继承关系。

小练习是从仓库根目录启动脚本后，脚本的 Path.cwd() 是否等于脚本父目录。通常不相等，必须观察实际值。

## 可复现实验
环境为 Python 3.11+ 和 PowerShell。只打印路径，不打开参数指向的文件。把下面的 H:/CodeX/Carreer/agent-industry-lab 换成你的仓库实际位置。命令里的引号是为让带空格的目录作为一个参数。

```powershell
Set-Location -LiteralPath 'H:/CodeX/Carreer/agent-industry-lab'
Get-Location
python llm-zero-to-one/examples/day018_working_directory_lab.py demo-input.txt
Set-Location llm-zero-to-one
python examples/day018_working_directory_lab.py demo-input.txt
```

若 python 不可识别，先用安装后的解释器完整路径替代程序名。在 PowerShell 中带引号的程序完整路径前要加调用符 &，例如下面是路径示意，需换成已安装的真实位置。

```powershell
& 'C:/your-python/python.exe' --version
```

完整[实验脚本](../examples/day018_working_directory_lab.py)第一段读取 Path.cwd() 得到当前目录，第二段用 Path(__file__).resolve().parent 定位脚本目录，第三段读取 sys.argv[1] 得到输入参数，第四段计算输入路径并打印。没有传参数时主动退出，提示提供一个路径。

预期第一次 cwd 为仓库根，第二次为仓库下 llm-zero-to-one。两次 script_dir 相同；input 则分别为根目录下 demo-input.txt 和 llm-zero-to-one 下 demo-input.txt。结果前缀以你实际路径为准。本次仅静态审查，课堂命令未执行。

## 看懂错误而不是反复重输
报 can't open file 常见原因是脚本相对路径的起点错了，先用 Get-Location 查看位置，再确认文件在哪。报 python 不识别是解释器查找问题，尚未执行到脚本。报 provide exactly one path 是本课脚本的参数数量错误，说明解释器和脚本已经找到。

PS H:/lab> 是常见终端提示符，表示当前窗口位置，不应把它作为命令输入。Python 交互提示符 >>> 表示你已进入解释器交互模式，它不能直接接受 Set-Location 这样的 PowerShell 命令，先退出再回到终端。

小练习是报“找不到 python”时修改 demo-input.txt 会有帮助吗？没有，定位解释器发生得更早。

## 练习与解释性答案
1. 在仓库根目录执行第二条 python examples/... 会怎样？脚本路径缺了 llm-zero-to-one，通常找不到脚本。修正路径或先切换到相应目录。
2. 用脚本绝对路径启动能保证脚本读对相对资料吗？不能，只固定了脚本位置，资料还取决于程序采用 cwd、脚本目录还是显式参数。
3. 给包含空格的路径不加引号会怎样？终端可能拆为多个参数，本课脚本会拒绝参数数量。给完整路径加引号再提交。
4. 当日交付是什么？记录两次 cwd、script_dir、input，解释哪项变化及原因；再写出一个无参错误和修正命令。运行结果与文中预期分开保存。
