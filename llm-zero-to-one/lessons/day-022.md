# Day022 列表装多条资料

检验员按先后把三张测量记录放进一个文件夹。程序中的列表也能把多条资料按位置放在一起。列表保留顺序，允许两条记录的值相同。文件夹类比只说明排列，列表里的位置会随着插入或删除改变，业务测点仍要保留自己的编号。

## 从单条到多条

先把一条读数写成二元组，例如 ("P10", 10003)。元组是一组按位置排列的值，这里第一项是测点，第二项是微米读数。再把多条元组放进方括号，形成列表。索引是从 0 开始的位置，因此 records[0] 是第一条。要处理每条记录，使用 for 逐项读取。

小题。三条记录的最后一项索引是多少？2，因为从 0 数起。若记录顺序改变，records[0] 会指向新的第一条，不能据此断言其测点仍是 P10。

## 加入一条记录或一组记录

append 接收一个对象并把它作为一项追加。extend 依次取出一组对象中的各项并追加。原列表有两条，新批次有两条时，append 会让外层长度从 2 变 3，最后一项是一组记录。extend 会让外层长度从 2 变 4，每项仍是一条记录。选择取决于后续要按批读取还是逐条读取。

小题。一次把两条资料放入文件夹，为何长度可能只加 1？因为 append 将装着两条资料的列表作为一个对象放入外层。若接下来按单条处理，结构不符可能让解包失败，也可能让程序悄悄把两条资料当字段。

## 实验与验收

准备 Python 3.11+，从仓库根目录运行 [课堂脚本](../examples/day022_list_records_lab.py)。

```powershell
python llm-zero-to-one/examples/day022_list_records_lab.py
```

脚本先做两份浅复制，得到可单独调整的外层列表。每条读数使用元组，示例只追加外层项目。分别使用 append 和 extend 后，预期打印 3 4，接着逐条打印 P10、P20、P30、P40 及读数。实际仅静态检查。若索引越界，先核查长度。若逐项读取时发现最后一项仍是列表，核查是否把整个批次追加成一项。

画一条输入到处理再到输出的箭头链。两批合成记录是输入，按测点读取是处理，逐点列表是输出。报告附来源，计量员核对测点和证书。再补一条 P10，写下反例和自查答案。列表允许重复，需由业务规则检查编号，不能仅凭总长度断言四个测点齐全。
