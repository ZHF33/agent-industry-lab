# 第十七期草稿　文本编码与换行

在[第十六期路径课](../lessons/day-016.md)找到文件后，还要把存储内容读成正确的文本。本期把字符、字节、编码、换行和模型输入串起来。课堂只在内存里操作一小段合成文字，适合没有 GPU 的环境。

## 同一张清单为什么在另一台电脑上显示乱码？

想象车间把“泵”写成一串约定数字，收件人按另一套约定读，可能看成其他符号或读不出来。**字符**是文本表示的单位，**字节**是存储与传输的数据单位，**编码**约定怎样把字符转换为字节。反向操作叫**解码**。类比的边界在于一个字节不必对应一个字符，部分编码还会受前后字节影响。

Unicode 为字符定义编号，称为码点。UTF-8 规定这些编号如何写成字节。字母 A 在 UTF-8 下是一字节 41，汉字“泵”是三个字节 e6 b3 b5，以上用十六进制表示。每两位十六进制数写一个字节。字符数、字节数和大模型的词元数是不同口径。

小问题：文件有六个字节，就一定有六个字符吗？不一定。本期样例中的汉字占三个字节，换行也可能由两种字符组合表示。

## 按字节画出换行

LF 是换行符，通常写作反斜线 n，字节为 0a。CR 是回车符，写作反斜线 r，字节为 0d。CRLF 是它们连在一起。编辑器可能把两种形式都显示成一次换行，底层字节仍不同。

课堂原文为“泵”、CRLF、A、LF。拆开是 3 + 2 + 1 + 1 = 7 字节。先按 UTF-8 解码，会得到五个 Unicode 码点。若读取层将 CRLF 归一为单个 LF，结果变为四个码点。可以只改变读取参数，观察原始字节和解码后的行边界如何分别变化。

## 读代码，分清编码与换行

这些是完整示例的片段，需配合文件阅读。

```python
raw = "泵\r\nA\n".encode("utf-8")
print(raw.hex(" "))
```

输入是 Unicode 字符串，encode 得到字节，hex 只是把字节显示成数字，方便查看不可见的换行。文件加载时通常反过来，从字节解码成字符串。

```python
with TextIOWrapper(BytesIO(raw), encoding="utf-8", newline=None) as stream:
    text = stream.read()
```

BytesIO 让内存字节像文件一样可读。TextIOWrapper 先解码，再按配置处理换行。newline=None 会识别通用换行并将它们转换为 LF。newline="" 识别这些行末形式并保留原换行字符。用 ascii(text) 查看转义后的字符串，可在终端编码不同的电脑上对比。

小问题：把 newline 改为 None 能修复错误的 ASCII 解码吗？不能。解码要先按正确编码处理字节。换行参数只决定读取后的行末如何表示。

准备 Python 3.11+，在 PowerShell 进入仓库根目录，运行[课堂例子](../examples/day017_encoding_newline_lab.py)。

```powershell
python llm-zero-to-one/examples/day017_encoding_newline_lab.py
```

预期如下，来自源码推导。

```text
bytes: e6 b3 b5 0d 0a 41 0a
decoded: '\u6cf5\r\nA\n'
None '\u6cf5\nA\n'
'' '\u6cf5\r\nA\n'
ASCII: UnicodeDecodeError
```

前三组文字都从同一份字节得到。换行归一仅在 None 模式发生。最后一行故意使用 ASCII，该编码无法解释汉字的 UTF-8 字节。它是一条预期错误分支。课堂脚本本次未执行。

## 放回实际资料处理流程

```text
来源文件 → 读取字节 → 按约定解码 → 按任务决定换行处理 → 解析字段或送入模型
```

例如设备点检导入器可能先读文本，再解析设备与点检项字段。[点检 Agent](../../examples/inspection-reconciliation-review/README.md)当前采用合成内置记录，这条文件读取链留给后续接入。来源编码应由数据提供方说明，人工核对抽样文本。哈希或数字签名校验要使用协议规定的字节形式，提前换行归一可能改变校验结果。

遇到 UnicodeDecodeError 时先确认声明的编码和来源。把错误设置成忽略可能静默丢字，导致设备字段变化。界面显示正常但按行拆分异常时，查看换行字节或转义形式。内容读对后才能检查字段，字段核对与模型推理各有独立验收。

## 练习与答案

1. 将样例第一处 CRLF 改为 LF，少几个字节？少一个 CR，所以从七变六。按 None 读取的逻辑文本相同。
2. 预处理把不同换行都转 LF，两个文件内容哈希会自动相等吗？原始字节可能不同。要先确认哈希针对原始字节还是约定的归一结果。
3. 模型能否帮忙猜编码？可以给候选，应用仍要查来源声明和实际解码证据。
4. 为什么课堂打印 ascii(text)？用可见转义明确换行和汉字码点，减少终端显示方式干扰。
