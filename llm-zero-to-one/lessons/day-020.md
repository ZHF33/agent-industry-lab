# Day020 变量与字符串

贴在箱子上的“00123”是编号。五个字符各有位置，开头两个零也有用。仓库台账上的数量 123 则可以拿来加减。两者看起来相近，程序需要保留不同的数据表示。

## 名字与值

变量像指向一张卡片的标签。Python 中赋值会把名称绑定到一个对象。名称 job_code 可以先绑定到字符串 "00123"，之后重新绑定到另一个字符串。若 snapshot = job_code，snapshot 当时绑定到同一个字符串。随后重绑 job_code 时，snapshot 仍指向原来的字符串。类比的边界是程序可以有多个名字引用同一个对象。字符串本身不可原地改写。

字符串是字符组成的序列。引号用来写文本，引号本身通常不属于值。len("00123") 得 5，len(str(int("00123"))) 得 3。先把它当整数时，转换只保留数量。再转回文本时，没有原始宽度可用。小题。把编号 00000 转整数再转字符串得到什么？得到 "0"，因为数值是零，原来有几个零已丢失。

## 逐步实验

准备 Python 3.11+，从仓库根目录运行 [课堂示例](../examples/day020_strings_lab.py)。

```powershell
python llm-zero-to-one/examples/day020_strings_lab.py
```

脚本先做两次绑定，再修改第一个名字的绑定。预期第一行显示 00999 00123。第二行显示 5 3，只改变数据表示。最后逐一检查正常编号、缺值、以及错传成整数的编号。预期状态依次为 valid、missing、invalid。课堂代码仅做静态检查，实际输出请自行记录。

格式检查同时要求文本、ASCII 字符、数字和五位长度。isdecimal 表示每个字符是十进制数字，也可能接受其他文字体系的数字，因此还检查 isascii。输入若为 None，表示缺证。空文本仍是一段文本，但长度不合格。小题。为什么不能先 str(123) 再检查？这种做法掩盖数据类型错误，而且恢复不了原来的零。

## 验收记录

交付三行用例。输入 "00123" 应有效，None 应判缺失，整数 123 应判类型错误。再加一个全角字符串 "００１２３"。它会因内部 ASCII 约定失败，生产系统应先定义是否允许规范化。若终端提示找不到脚本，先检查目录。若出现 TypeError，回看是否对非文本先执行了长度检查。
