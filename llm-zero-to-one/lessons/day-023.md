# Day023 字典表示业务对象

一张点检卡有“工位”“时间”和“状态”三个栏。即使表格交换栏位，读者仍能按栏名找到信息。Python 的字典也用名称找值。名称叫键，关联的数据叫值。纸卡可以有两个同名栏，字典中同一个键只保留一个值。

## 键如何关联值

用 {"point": "rack", "state": "clear"} 表示一条观察。花括号围住键值对，冒号连接键和值。record["state"] 根据键取得 clear，无需知道它原本排第几。读取必填键前先核验是否存在，缺键与键存在但值为 None 是两种情况。

小题。字典 {"state": None} 与空字典的 get("state") 返回什么？都会得到 None。想区分两种情况，可以先问 "state" in record，再看值。这个区别会影响补录还是修复数据契约。

## 按编号归组

用点检编号作键，一条记录可以用字典表示，多条观察可以作为同一个键下的列表。若每次直接写 grouped[point] = state，两次给 rack 赋值后，后值覆盖前值。若用 grouped.setdefault(point, []).append(state)，先取已有列表，若键不存在则建立空列表，再追加一项。后续仍需比较时间来判断是否冲突。两个值不同只说明存在差异，同一时刻出现差异才满足本案例的冲突规则。

小题。把两条 rack 状态按相反顺序输入，覆盖法的输出会怎样？会随输入次序改变。归组法保留两条，工具才能按真实时间选择。

## 实验

准备 Python 3.11+，从仓库根目录运行 [课堂脚本](../examples/day023_dictionary_lab.py)。

```powershell
python llm-zero-to-one/examples/day023_dictionary_lab.py
```

脚本处理三条合成输入。第一条写入 rack 已清，第二条写入 rack 有余料，第三条写入 bin 但状态未填。程序先按键验证字段，再分别做覆盖和归组。预期先打印 residue，第二行打印 ['clear', 'residue']，第三行打印 missing value。另有一条无 state 的记录，预期打印 missing key。实际仅静态检查。若出现 KeyError，先确认必填键及拼写，再决定是退回记录还是允许缺值。

交付逐步手算表，记录每次写入后 rack 键下的值，再交换前两条输入比较。答案是覆盖结果变为 clear，归组保留两项且顺序反转。程序中的结构决定了报告能看到哪些证据。Agent 工具应保存事件时间和编号，人工才有条件核对来源。
