# Day 025 循环处理记录

## 把四张检验单一张张过一遍

桌上有四张单，A 写合格，B 写不合格，C 状态栏空白，D 写了无法识别的 7。每看一张，更新小计，或将单号放到待核栏。程序可以重复同一组步骤。人工看单还会辨认手写字，程序本课只接受事先约定的字段值。

单张单据用字典表示，字段名如 id 和 status 是键。把四张单放进列表。循环是按规则重复动作。Python 的 for 每取到列表中的一项，就把该项交给临时变量 record，再执行缩进的循环体。列表走完后，程序跳到循环体之后。小计由我们主动更新，循环自身不会产生合格数。

**小问题**　空列表会执行几次循环体？

**解释**　零次，没有一项能绑定到 record。循环外预置的计数仍为 0。空列表可能代表没有数据，也可能是读取范围出错，调用方需核对来源。

## 把每轮的数据变化画出来

[课堂脚本](../examples/day025_record_loop_lab.py) 先创建 summary，包含合格计数、不合格计数和待核单号列表。下面是用于讲解的片段，须在完整脚本中运行。

```python
for record in records:
    status = record.get("status")
    if status == "passed":
        summary["passed"] += 1
    elif status == "failed":
        summary["failed"] += 1
    else:
        summary["issues"].append(record["id"])
```

get 读取状态，缺这个键时返回 None（表示没有值）。if、elif 和 else 使每一张单恰好进入一条分支。+= 1 读取旧小计、加一、存回同一键。append 把一个单号放到待核列表末尾。完整脚本中的 return 与 for 对齐，等名单都处理后才把 summary 交给调用方。

| 处理完 | 合格数 | 不合格数 | 待核单 |
| --- | --- | --- | --- |
| 尚未开始 | 0 | 0 | 无 |
| A | 1 | 0 | 无 |
| B | 1 | 1 | 无 |
| C | 1 | 1 | C |
| D | 1 | 1 | C、D |

每轮后，合格数加不合格数再加待核数量，应等于处理过的记录数。这个关系叫循环不变量，即在每一步都应成立的检查条件。若 C 被悄悄忽略，第三轮后右侧为 3，左侧仍为 2，能发现漏记。若数据源把同一张单送来两次，该关系仍成立，因为它数的是列表元素。按业务单号去重需要单独设计。

**小问题**　把 C 的状态改成 failed，其他值保持原样，什么会变？

**解释**　C 会进入不合格分支，不合格数从 1 到 2，待核只剩 D。合格数不变，三个分类仍合计四条。

## 动手检查

准备 Python 3.11 或更新版本，在终端切换到仓库根目录。没有模型和 GPU 前提。执行：

```powershell
python llm-zero-to-one/examples/day025_record_loop_lab.py
```

预期输出如下。课堂代码本次仅静态检查和手推。

```text
passed 1
failed 1
issues C,D
```

若只得到 A 的结果，检查 return 是否写进循环体。若出现 KeyError 并指向 id，说明待核行缺少单号，当前教学脚本假定每张单都有 id。实际导入可记录位置并拒绝缺身份的行。将记录列表清空后应得到两个零和空待核列表。不要把空列表转述为产线零缺陷。

## 和 Agent 的关系

普通 for 的下一项由列表顺序决定。模型工具循环中，程序把上次工具结果加到模型输入消息，再让模型决定是否继续、选什么工具。源系统对工具名、参数和轮数负责。清点成功、失败和待核的循环可用确定性规则执行，模型可以读这些结果并据此组织说明。适合验收的交付是四张单的逐轮表、一处单变量改动与预测输出，再指出哪个条件能发现漏记、哪个无法发现重复。
