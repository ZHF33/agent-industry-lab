# Day 003｜训练与使用：模型到底什么时候“学进去”了？

[课程首页](../README.md) · [计划](../PLAN-365.md) · [原理主线](../PRINCIPLES-AND-SOURCE-MAP.md)

前置：第一期模型/参数概念和第二期输入组装。无需GPU、账号或付费服务；纸笔路线可独立完成。数学加深部分可第二遍再读。

**今天解决：为什么把正确答案告诉聊天助手，通常不等于模型参数已经更新？** 交付两条流程图和一张“改变了什么”的对照表。

## 1. 一次纠正之后，发生了什么？

合成面包店助手把单价说成8元，你告诉它：“商品卡写8.50元，请按这个算。”下一轮它说12个合计102元。能断言它已经经过一次微调了吗？

不能。第二期知道，应用可能把你的纠正放入下一次输入。模型利用新输入生成不同结果，不必改变参数。这种变化和“训练后换了一套参数”要分开。

生活类比是开卷考试：把正确材料放在桌上，考生当场可查，与长期练习形成能力不同。类比边界是模型不具备人的学习体验；我们真正检查的是计算流程中是否发生参数更新，而不是猜它有没有“想明白”。

小问题：助手说“我记住了”，能作为参数更新证据吗？**不能。** 这句话是生成内容。可能只是这轮上下文起作用，也可能应用保存了偏好，还要看实际系统机制。

## 2. 三个东西：参数、输入、输出

用一个短记号表示：

`输出 = 模型(输入；参数)`

这里分号只是帮助把两类东西分开，不是你需要执行的代码。**参数**是训练得到的数字；**输入**是本次交给模型的任务、资料和历史等；**输出**是模型基于它们生成或预测的结果。

普通使用阶段常称**推理（inference）**，在这里指用已有参数做计算，不专指“解一道逻辑推理题”。让模型改写一句话，也是在做inference。把技术术语和日常中文分开，读文档就不会误会。

即使参数不变，换输入也会改变中间表示和输出。像计算器公式不变，12换成13结果会变；这不说明计算器自己改了乘法规则。模型远比计算器复杂，但“输入变化”和“参数变化”仍是两条不同路径。

## 3. 训练比普通使用多哪几步？

先给两条流程：

```text
普通使用：已有参数 + 当前输入 → 计算 → 预测/生成 → 返回结果

一次训练更新：当前参数 + 训练样本 → 预测
                                      ↓
                              与训练目标比较，算损失
                                      ↓
                              计算参数方向，更新参数
                                      ↓
                               新参数用于后续计算
```

**训练目标**告诉训练过程希望提高什么表现；**损失**是把预测与目标的差距变成一个数；**梯度**描述参数变化对损失的局部影响；**优化器**按规则使用这些信息更新参数。先认识职责，不要求现在会矩阵求导。

普通生成也会做大量数值运算，还可能维护缓存或应用状态。“没有参数更新”不等于“没有计算，也不存任何东西”。训练系统、模型服务和应用存储仍要分清。

## 4. 训练样本里的“答案”从哪里来？

自回归语言模型预训练时，可以把文本前面部分作为条件，用实际后续片段作目标。例如教学句子“今天烤面包”，可以形成预测后续片段的任务。真实分词未必按字切，这里仅说明目标如何从原文构造。

这种从数据自身产生训练信号的方法叫**自监督学习**。它不意味着完全没人参与：采集、过滤、去重、数据许可和训练目标都需要设计。也不是所有语言模型使用完全一样的训练任务。

**监督微调**则可使用任务与合适回答配对的资料，让已有模型继续适应特定行为。它会经过训练更新；在提示里放两个范例，通常只是改变当前输入，不能仅因出现“范例”就叫微调。

“训练目标”也不是“现实世界的全部真理”。如果目标数据错误，优化器也可能朝错误方向改；如果样本只覆盖一种情况，训练变好不表示新任务都能做好。

## 5. 手算一个只有一个参数的小模型

下面是原创数学玩具，**不是大语言模型，也不能识别真实订单**。目的只是让“参数真的改变”变成看得见的数。

设输入只有一个数字x，参数只有一个数字w。先算分数`z=w×x`，再用sigmoid把它转成0到1之间的数p：

`p = 1 / (1 + exp(-w×x))`

exp是指数函数。暂时把p看作模型给“类别1”的概率；类别0概率为1-p。它是不是可靠概率还需要评估，不能把公式输出当成现实置信保证。

初始w=0，输入x=1，真实目标y=1。因为分数为0，exp(0)=1，所以p=1/(1+1)=0.5。模型对这一个训练目标还没有偏向。

为目标y=1定义损失`L=-ln(p)`，ln是自然对数。p=0.5时L约0.693147；若p更接近1，这个目标的损失会下降。这里只选正类样本方便讲解，完整二分类损失还要处理y=0。

## 6. 一次更新到底改了什么？

对于上面的sigmoid加二分类交叉熵，w的梯度为：

`梯度 = (p-y)×x`

这是本玩具结构对应的结果，不是所有模型都能套同一个梯度公式。现在代入0.5、1、1，梯度为-0.5。

**学习率**控制更新步子的尺度。取教学学习率1，最简单的更新：

`新w = 旧w - 学习率×梯度 = 0 - 1×(-0.5) = 0.5`

参数从0变成0.5，这是一次真实定义的参数更新运算。新输入仍为x=1时，p约0.622459，损失约0.474077，比之前小。

这里有三条边界：只演示一个样本的一步；学习率1不是LLM训练推荐设置；这一个样本损失下降不证明全体数据或业务效果提升。真正训练需要更多样本与独立检查。

小问题：损失降低后是不是已经“学会面包店业务”？**不是。** 玩具根本没读文字，也没有学任何店铺事实；它只让你看到参数如何按目标变化。

## 7. 只换输入，也能改变结果

把刚更新的w固定为0.5，不再更新。输入x从1变成2，则分数从0.5变成1，p约0.731059。结果变了，参数仍是0.5。

| 操作 | 输入x | 参数w | 类别1的p |
| --- | ---: | ---: | ---: |
| 更新前计算 | 1 | 0 | 0.500000 |
| 一步更新后计算 | 1 | 0.5 | 0.622459 |
| 固定新参数，仅换输入 | 2 | 0.5 | 0.731059 |

第二行变化来自参数更新，第三行来自输入变化。真正语言模型的提示会变成词元与更复杂表示，不是把一句中文直接当成数字2；类比只说明两条改变路径不同。

纸笔验收：遮住第三列，说明哪行必须有训练步骤；再遮住第四列，解释为什么没有训练也可能换答案。说清“哪一个对象变了”，才不是背术语。

## 8. 少样本提示为什么不等于训练？

给模型两个“资料不足→指出缺项”的例子，然后让它处理新商品卡，这叫少样本提示的一种用法。范例进入当前条件，影响生成，不必调用优化器或保存新权重。

上下文学习里的“学习”描述一种任务表现，并不自动表示一次梯度更新。GPT-3论文的少样本实验明确区分了这种使用方式与参数微调；这不代表所有未来系统都永远禁止在线更新，而是本课讨论的标准用法需要分清。

后续真实实验中可以固定同一模型版本，比较有/无范例的输入，保留任务与验收标准；但一次答对不能证明永久掌握，重复输出也不证明内部参数从未变动。机制判断还需要系统记录。

## 9. 更新资料、保存记忆、微调应该怎么选？

| 需求 | 优先检查的路径 | 理由 |
| --- | --- | --- |
| 今天商品改价 | 权威资料、检索、缓存与输入版本 | 事实频繁变化，需要可追溯更新 |
| 同一对话改成简短语气 | 当前指令与历史 | 任务条件可直接说明 |
| 下次还沿用用户偏好 | 应用保存偏好并在授权下取用 | 跨会话保存通常是应用职责，不必先改模型参数 |
| 稳定适应大量同类任务 | 先做任务评估，再考虑高质量数据和微调 | 训练有成本与过拟合等风险，不因答错一次就启动 |

这不是“微调绝对不能学习新知识”。训练可以影响知识与能力；但拿它维护每分钟变化的库存，通常会遇到更新、来源追溯和验证问题。RAG与微调也能组合，不能硬分成互不兼容的路线。

## 10. 可选代码，逐段看输入与结果

完整[day003_learning_lab.py](../examples/day003_learning_lab.py)仅依赖Python标准库math。输入是写在程序内的一组教学数字，没有模型、网络或文件写入。

第一段probability函数：输入weight与feature，计算公式并返回p。第二段positive_loss：输入p，返回正类样本损失。第三段main：保存旧参数，算梯度，得到新参数，打印对比；最后只换输入，不再更新。

关键三行摘录，不能单独运行：

```python
before = probability(weight, feature)
gradient = (before - target) * feature
updated_weight = weight - learning_rate * gradient
```

变量weight是数字名字，不是真实LLM权重文件。updated_weight单独保存，便于对比更新前后。没有自动求导库：我们把这个结构的梯度公式明确写出来；这不能代替以后学习复杂模型的反向传播。

运行前提为Python3.12+。在完整仓库目录手动执行：

```powershell
cd H:\CodeX\Carreer\agent-industry-lab\runtime\publish-20261014
python llm-zero-to-one/examples/day003_learning_lab.py
```

其他读者替换cd路径。预期输出，**本次未执行**：

```text
p_before: 0.500000
loss_before: 0.693147
weight_after_step: 0.500000
p_after_step: 0.622459
loss_after_step: 0.474077
inference_other_input: 0.731059
weight_after_inference: 0.500000
```

看代码最后一行：普通计算结束后参数仍然0.5。运行这个几十行数学玩具，也不能称为“本地大模型训练成功”。

## 11. 故障与对照练习

若python不是命令，说明解释器前提未满足；今天可以只做纸笔练习。文件找不到先确认当前目录；SyntaxError先核对括号与缩进。不要因为要学训练，就先下载一个占满显存的大模型。

对照一：只把学习率改成0。预期新参数仍为0，训练步骤虽然被计算，但这一步没有实际参数变化。说明看到“训练流程”也要核对更新是否发生。

对照二：固定w=0.5，分别输入x=0、1、2。预期p约0.5、0.622459、0.731059；w不变。输入变动足以让输出改变。

对照三：故意把目标y改成0，却仍使用positive_loss观察，会怎样？**会把监督口径弄错。** 梯度更新与显示的损失不再指向同一个目标。完整二分类应使用`-y×ln(p)-(1-y)×ln(1-p)`，还要考虑数值边界。本例限定y=1；不能随便改目标后仍声称输出是正确训练证据。

## 12. 五题验收与解释性答案

**一：答案变好了，是否证明训练发生？** 否，输入、工具结果、缓存和模型版本等都可能改变。先查系统流程与实际参数版本。

**二：推理是不是只指模型解数学题？** 否，inference指用已有模型做预测或生成，改写文字也属于使用。

**三：训练与推理都要计算，区别只在速度吗？** 否，标准训练包含目标、损失与参数更新；速度和资源消耗不是唯一判定。

**四：一个样本损失下降，为什么不代表其他样本更好？** 更新可能只适应该样本，其他输入表现需独立评估，不能拿训练题冒充未见题。

**五：用户纠正被应用保存，未来会不会参与训练？** 可能存在另行授权和治理的训练流程，取决于具体产品政策。不能因当场纠正就认定已更新，也不能无依据承诺所有服务永不使用数据。

交付两条流程图，标出参数更新的位置；再用自己的业务例子列“改输入、改资料、改应用存储、改参数”各一种。每一项写出需要怎样的证据确认它发生过。
