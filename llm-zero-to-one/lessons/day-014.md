# 第十四期　合成资料与隐私

前置为[第十三期输出验收](day-013.md)。这次交付一份可以公开的合成验收资料。先定义要验证的行为，再构造所需字段，最后检查导出的内容。

## 为什么演示资料容易泄漏

班组长想展示 Agent 怎样找出交班缺口。如果复制真实班次再改姓名，仍可能留下工号、备注、真实日期、车间位置，甚至独特的时间组合。知道上下文的人可能把这些信息重新对应到个人。演示只需要“重叠”“跨边界”“存在缺口”三种行为，完全可以独立构造这些条件。

类比是驾驶考试用的模拟路段。它要保留转弯和停车等要测行为。真实道路的姓名、车牌和行程与这次练习无关。类比的边界在于数据也会被链接、保存和传播，公开前还要审查完整文件。

## 合成、遮盖与字段投影

**合成资料**是按测试目的人工编造或程序生成的样例。今天手工构造四小时窗口，并放入三条虚构区间。它与某个真实班次没有一一对应关系。

**遮盖**是替换已有资料中的一部分内容。若把真实工号换成 DEMO-01，仍保留其他真实信息，就应继续判断能否关联。**字段投影**只挑出任务允许的字段。字段投影适合减少数据量，但保留下来的值仍需审查。由真实资料训练或拟合得到的合成数据也可能保留罕见模式，本课采用独立编造的固定样例。

小问题：只把人名删掉，能直接发布吗？还需检查组合信息、自由文本以及其他文件中可能出现的关联线索。

## 用数字反推最少输入

目标是检验“覆盖时长不会因重复计算而增加”。构造一个 240 分钟窗口，覆盖 220 分钟，缺口 20 分钟。预期 `覆盖 + 缺口 = 窗口长度`。这里三项都是分钟。故意增加一条完全落在已覆盖范围内的记录，预期覆盖仍为 220 分钟。这个对照只变更一项输入，便于定位失败。

公开验收摘要只需要虚构班次 ID、窗口分钟数与缺口分钟数。班组姓名、联系方式和自由备注不参与计算。完整运行夹具还需要记录端点与合成来源 ID，因为计算器必须重建区间。摘要与运行夹具的字段按各自用途决定。实例可见[交班覆盖 Agent](../../examples/shift-coverage-review/README.md)。

## 用白名单固定导出

以下为代码片段，完整文件见[课堂例子](../examples/day014_synthetic_projection_lab.py)。

```python
PUBLIC_FIELDS = ("shift_id", "window_minutes", "gap_minutes")

def project(record):
    return {key: record[key] for key in PUBLIC_FIELDS}
```

record 是一条由键和值组成的字典。白名单固定三个可导出的键。循环逐个取值，生成一个新字典。新增备注字段时，输出结构不变。缺失必需字段会报 KeyError，这能让配置错误显现出来。生产接口应将错误映射成明确的输入校验结果。

与“先全量复制再删姓名”相比，字段白名单给新增字段一个可预期的默认行为。值是否合法仍要独立校验。比如把真实姓名写进 shift_id，字段投影仍会把它带出去。实际系统还应限制值来源、检查嵌套内容，并结合数据访问权限控制。提示词中的“注意隐私”无法替代这些程序行为。

## 离线验证

准备 Python 3.11+，在 PowerShell 进入仓库根目录。

```powershell
python llm-zero-to-one/examples/day014_synthetic_projection_lab.py
```

预期输出如下，来自静态推演。

```text
{'shift_id': 'SHIFT-DEMO-A', 'window_minutes': 240, 'gap_minutes': 20}
note exported: False
```

增加一个模拟的内部备注，输出仍应只有三个键。删除 gap_minutes，应出现 KeyError。若修改保留字段的值，输出会跟着变化，这正是还需审查值的原因。本例使用固定合成输入，未执行脚本、测试或模型。

## 常见问题与练习

| 现象 | 检查方向 |
| --- | --- |
| 正文安全但提交里有日志 | 核对暂存区、运行文件和附带样例 |
| 字段名称正常但值像真资料 | 核查取值来源与自由文本 |
| 演示跑过但结论不稳 | 增加合成边界例和失败例，分别记录证据 |
| 替换姓名后仍能认出人员 | 检查时间、地点和稀有组合 |

1. 需要展示重复记录，最少要造什么？同一窗口内两条相交记录，加一个确定的预期覆盖值。姓名与实际日志无关。
2. 用白名单后新字段会自动公开吗？只有列入白名单才会导出。已允许字段的值仍需检查。
3. 三条合成样例都通过能说明什么？仅说明这三个用例的实际验收结果。规模、真实部署和隐私边界需要各自的证据。
4. 调换两条记录的输入顺序会怎样？排序后计算结果应一致。这是另一条可独立设计的验收用例。

当日交付为三条合成测试记录、各自的预期结果、一份字段白名单和一条保留字段装错值的反例。
